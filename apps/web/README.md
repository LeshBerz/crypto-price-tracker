# @cpt/web — дашборд и панель оператора

Веб-клиент к [`apps/api`](../api): Next.js 16 (App Router) как BFF и UI. Это дополнение к сдаваемой версии: ограничения ТЗ на него не действуют, а `apps/api` от него не зависит — образ api собирается и запускается без этого каталога.

**Состояние:** каркас, вход, выход и серверные сессии (C1); BFF к api, поток событий и Docker-образ (C2); дашборд (C3); карточка монеты (C4); панель оператора (C5); пользователи, сессии и профиль (C6). Гид по интерфейсу и e2e-сценарии — следующие задачи фазы C в [ROADMAP](../../ROADMAP.md).

**Стек:** Next.js 16.4 · React 19 · TypeScript · Tailwind CSS 4 · shadcn/ui на Base UI · `node:sqlite` (raw SQL) · Jest.

## Запуск

Нужен Node.js ≥ 24.15 (версия — в `.nvmrc`). Из корня репозитория:

```bash
npm ci
```

Web читает общий файл окружения — `.env` в корне репозитория, тот же, что api и `docker compose`. Шаблон со всеми переменными — [`.env.example`](../../.env.example):

```bash
cp .env.example .env
```

В нём нужно заполнить четыре значения.

Два ключа api — команду выполнить дважды, значения должны различаться. api примет их при старте, web будет ходить с ними в api:

```bash
node -e "console.log('cpt_' + require('node:crypto').randomBytes(32).toString('base64url'))"
```

```dotenv
BOOTSTRAP_VIEWER_KEY=cpt_…
BOOTSTRAP_OPERATOR_KEY=cpt_…
```

Первый оператор: логин и хэш пароля. Команда спросит пароль (от 12 символов) и напечатает хэш:

```bash
npm run hash-password -w @cpt/web
```

```dotenv
WEB_BOOTSTRAP_LOGIN=admin
WEB_BOOTSTRAP_PASSWORD_HASH='scrypt$17$8$1$…'
```

Хэш — в одинарных кавычках, знаки `$` не экранируются. Без ключей web не стартует и называет переменную, которой не хватает.

### Локальный стенд

Три процесса: источник цен, api и web. Все команды — из корня репозитория, каждая в своём терминале, в этом порядке.

Источник цен — на выбор:

- **стаб CoinMarketCap** (ключ и интернет не нужны): в `.env` задать `CMC_API_KEY=stub-cmc-key` и `CMC_BASE_URL=http://localhost:4010`, затем запустить стаб:

  ```bash
  node apps/api/scripts/cmc-stub-server.ts
  ```

- **настоящий CoinMarketCap**: в `.env` задать свой `CMC_API_KEY`, строку `CMC_BASE_URL` убрать или закомментировать. Стаб не запускается.

api:

```bash
npm run dev -w @cpt/api
```

web:

```bash
npm run dev -w @cpt/web
```

| Процесс | Адрес | База |
|---|---|---|
| Стаб CoinMarketCap | http://localhost:4010 | — |
| api | http://localhost:3000, Swagger — `/docs` | `apps/api/data/cpt.db` |
| web | http://localhost:3001 | `apps/web/data/web.db` |

Что нужно знать:

- **Стаб знает три монеты:** BTC, ETH и MEME. Остальные символы api отклонит с 422.
- **Цены появляются после синхронизации:** по расписанию раз в 5 минут или кнопкой «Запустить» в `/operator/sync`.
- **С настоящим CoinMarketCap тратится квота:** 1 кредит на синхронизацию всего списка, расход виден в `/operator/system`.
- **Запускать web нужно одной и той же командой.** Путь к базе относительный: запуск из другого каталога создаст вторую базу с другим набором пользователей.
- **Начать заново:** остановить процессы и удалить каталоги `apps/api/data` и `apps/web/data`. Базы и первый оператор создадутся при следующем старте.
- **`CMC_BASE_URL=http://localhost:4010` годится только для локального запуска.** Перед `docker compose up` строку нужно закомментировать: в контейнере `localhost` — это сам контейнер.

### Откуда берутся значения

| Источник | Приоритет | Когда нужен |
|---|---|---|
| Переменные процесса | высший | Docker, CI, разовое переопределение в терминале |
| `apps/web/.env.local` | выше общего файла | Значения только для web на этой машине. Этот файл читает сам Next и подставляет переменные: знаки `$` в хэше здесь экранируются (`scrypt\$17\$…`) |
| `.env` в корне | базовый | Обычный случай: один файл на весь проект |

Из общего файла web берёт только свои переменные; ключ CoinMarketCap в процесс web не попадает.

## Переменные окружения

Полный список с валидацией — [`src/server/config.ts`](src/server/config.ts), шаблон — [`.env.example`](../../.env.example) в корне репозитория.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_BASE_URL` | `http://localhost:3000` | Адрес api: только origin, без пути |
| `API_VIEWER_KEY` | значение `BOOTSTRAP_VIEWER_KEY` | Ключ api роли viewer: им BFF ходит за ценами и в поток событий. Один из двух обязателен |
| `API_OPERATOR_KEY` | значение `BOOTSTRAP_OPERATOR_KEY` | Ключ api роли operator. Должен отличаться от ключа viewer |
| `API_TIMEOUT_MS` | `10000` | Сколько ждать ответа api; дольше — 504 |
| `WEB_DATABASE_PATH` | `./data/web.db` | SQLite с пользователями и сессиями. Отдельный файл, не БД api |
| `WEB_BOOTSTRAP_LOGIN` | — | Логин первого оператора. Создаётся при старте, если такого логина ещё нет |
| `WEB_BOOTSTRAP_PASSWORD_HASH` | — | Хэш его пароля (не сам пароль). Задаётся только вместе с логином |
| `WEB_TRUST_PROXY` | `false` | `true`, если перед web стоит обратный прокси: тогда учитываются `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host` |

### Docker

Web включается в общий compose профилем. Обычный `docker compose up` его не собирает и не запускает — сдаваемая версия поднимается как раньше.

В файле `.env` рядом с `docker-compose.yml` задать ключи api (их же api примет при старте), логин и хэш пароля. Хэш — в одинарных кавычках, чтобы compose не принял `$17` за переменную:

```
BOOTSTRAP_VIEWER_KEY=cpt_…
BOOTSTRAP_OPERATOR_KEY=cpt_…
WEB_BOOTSTRAP_LOGIN=admin
WEB_BOOTSTRAP_PASSWORD_HASH='scrypt$17$8$1$…'
```

```bash
docker compose --profile web up --build
```

Приложение — на http://localhost:3001 (порт меняется переменной `WEB_PORT`). Без ключей контейнер web останавливается на старте с сообщением, какой переменной не хватает. Образ: `node:24-alpine`, пользователь `node`, сервер из `.next/standalone`, БД сессий — в volume `web-data`.

## Как web ходит в api

Решения — [ADR 0016](../../docs/adr/0016-web-auth-and-bff-routes.md), разбор — [docs/study/15](../../docs/study/15-bff-и-sse-прокси.md).

Браузер не знает ни адреса api, ни его ключей. Он обращается к web, а web — к api:

| Маршрут web | Что делает |
|---|---|
| `/api/bff/<путь api>` | Прокси по таблице разрешённых операций. Пример: `GET /api/bff/api/v1/prices` |
| `GET /api/stream` | Поток событий api (SSE). Сессия перепроверяется каждые 25 секунд |
| `GET /api/health` | Готовность самого web (для healthcheck контейнера) |

- **Таблица** [`src/server/bff/allowlist.ts`](src/server/bff/allowlist.ts): 15 строк «метод + путь → минимальная роль». Запроса нет в таблице — 404, в api он не уходит. Тест сверяет таблицу с `openapi.yaml`: новая операция без строки в таблице — красный CI.
- **Ключ по роли:** сессия viewer → ключ viewer, сессия operator → ключ operator. Если BFF ошибётся, api сам ответит 403 по правам ключа.
- **Ответы api** проходят как есть: статус, тело, ошибки RFC 9457, `Location`, `Retry-After`, `X-Request-Id`. Один `X-Request-Id` — в логах web и api.
- **api недоступен:** 502, не ответил за `API_TIMEOUT_MS` — 504; оба в формате RFC 9457 с типом `urn:cpt:web:problem:*`.
- **Поток** закрывается сам после выхода, отзыва сессии или отключения пользователя — на ближайшем heartbeat, с событием `session.expired`. Открытый поток не продлевает срок бездействия сессии.
- **Типы** ответов api — [`src/generated/api-types.ts`](src/generated/api-types.ts), генерируются из `openapi.yaml`.

## Дашборд

- **Три запроса** на весь экран, независимо от числа монет: цены, мини-графики, список монет (признак паузы).
- **Таймера опроса нет.** Новая цена приходит событием `price.updated` и пишется в кэш запросов; `sync.finished` и `watchlist.changed` перечитывают данные.
- **Срок бездействия работает и на открытой вкладке:** перезапросы по событиям идут с заголовком `X-Cpt-Background: 1` и сессию не продлевают.
- **Сбой виден, данные остаются.** api недоступен, цены устарели, запуск синхронизации не удался, поток отключён — один баннер с самой серьёзной причиной. Монета на паузе сбоем не считается.
- **Цены — строки:** форматирует `Intl.NumberFormat` из строки, в `number` цена не переводится.

Клиентская логика лежит в [`src/lib/`](src/lib) без зависимости от React и проверяется тестами в Node. Разбор — [docs/study/16](../../docs/study/16-дашборд-и-realtime.md).

## Как устроен вход

Решения и обоснование — [ADR 0016](../../docs/adr/0016-web-auth-and-bff-routes.md), разбор — [docs/study/14](../../docs/study/14-web-вход-и-сессии.md).

- **Пароль** хранится как `scrypt` (N = 2^17, r = 8, p = 1), считается асинхронно, сравнивается через `timingSafeEqual`.
- **Сессия** — случайный токен 256 бит в cookie `HttpOnly; SameSite=Lax` (по HTTPS — `__Host-…; Secure`). В БД лежит только SHA-256 токена.
- **Сроки:** 2 часа бездействия, 12 часов всего. Выход отзывает сессию на сервере.
- **Подбор пароля:** после 5 неудач по паре «логин + адрес» — ожидание 1, 2, 4 … секунд, до 15 минут. Аккаунт целиком не блокируется.
- **CSRF:** `SameSite=Lax`, тело только `application/json`, заголовок `Origin` обязан совпадать с адресом web.

| Маршрут | Что делает |
|---|---|
| `POST /api/session` | Вход: `{ login, password }` → 200 и cookie; 401, 429 + `Retry-After`, 400, 403, 415 |
| `GET /api/session` | Кто вошёл: `{ login, role }` или 401 |
| `DELETE /api/session` | Выход: 204, сессия отозвана |

## Карточка монеты

`/coins/[id]` — переход по символу монеты с дашборда.

- **График** — Lightweight Charts: свечи или линия, светлая и тёмная тема. Интервал бакета (1 ч, 4 ч, 1 д, 1 нед) × период (24 ч, 7 д, 30 д, 1 год); сочетания сверх 1000 бакетов (предел api) и меньше двух неактивны и объясняют причину.
- **Обновление без запросов:** `price.updated` меняет цену в шапке, последнюю свечу и первую строку истории. Сводку и среднее считает сервер — они перечитываются по `sync.finished`.
- **Сводка** за период и **история** сырых точек с кнопкой «Загрузить ещё» (курсор api).
- **Цена становится `number` только в координатах графика.** Подсказка под курсором, сводка и история показывают строки api.
- **Монеты нет** (неверный адрес, 404 от api, удаление при открытой карточке) — экран «Монета не отслеживается».
- Шкала времени графика — UTC: по нему выровнены бакеты.

Поток событий один на вкладку: соединение открывает layout, экраны читают кэш запросов. Разбор — [docs/study/17](../../docs/study/17-карточка-монеты-и-график.md).

## Панель оператора

`/operator/*` — только для роли Operator. Роль проверяет серверный layout (разметка) и BFF (данные); Viewer по прямой ссылке видит «Недостаточно прав».

| Раздел | Что умеет |
|---|---|
| `/operator/watchlist` | Добавить монету (символ + необязательный CMC ID), переименовать, поставить на паузу и возобновить, удалить с подтверждением вводом символа |
| `/operator/sync` | Запустить синхронизацию вручную, журнал запусков с догрузкой по курсору |
| `/operator/system` | Доступность CoinMarketCap, последняя ошибка, квота месяца, готовность сервиса (`/health/ready`) |

- **Запись идёт через тот же BFF:** `bff.send('post' | 'patch' | 'delete', путь, …)` — путь, тело и ответ типизированы контрактом api.
- **Экран обновляется из ответа api,** а не по событию и не оптимистично: до ответа ничего не меняется, отката нет.
- **Ответы api на добавление монеты** (201, 400, 409, 422, 503) — у каждого своё сообщение; при 503 кнопка ждёт `Retry-After`.
- **Ручной запуск отвечает 202:** строка `идёт` появляется сразу, итог приносит событие `sync.finished`. Опроса нет; при отключённом потоке — кнопка «Обновить».
- **«Следующий запуск», «Расписание» и прогноз квоты** показываются, только если api отдаёт блок `schedule` (контракт 1.1.0 — `main`). С api сданной версии (`v1.0-submission`, контракт 1.0.0) этих строк нет.

Разбор — [docs/study/18](../../docs/study/18-панель-оператора-и-мутации.md).

### Данные для графика при разработке

Стаб CoinMarketCap отдаёт неизменную котировку, поэтому история сама не накапливается. Для локальной БД api:

```bash
node apps/web/scripts/seed-price-history.ts --db <файл БД api> --days 30
DATABASE_PATH=<тот же файл> npm run rollups:rebuild -w @cpt/api
```

Скрипт дописывает случайное блуждание цены перед самой ранней точкой каждой монеты. Только для разработки: он пишет в таблицу api напрямую, api на время записи лучше остановить.

## Пользователи, сессии и профиль

| Адрес | Кому | Что можно сделать |
|---|---|---|
| `/operator/users` | Operator | Создать пользователя, сменить роль, отключить и включить, сбросить пароль, отозвать любую сессию |
| `/profile` | любая роль | Свои сессии (текущая помечена), завершить другую сессию, выйти на всех устройствах, сменить пароль |

- **Данные — в `web.db`.** Маршруты `/api/admin/*` и `/api/me/*` в api не ходят. Контракт — общие типы [`src/lib/account/contract.ts`](src/lib/account/contract.ts): их импортируют и обработчики, и клиент.
- **Пароль создаёт сервер** и показывает один раз — при создании и при сбросе. В базе только хэш. Свой пароль пользователь меняет в профиле, указав текущий.
- **Последнего активного оператора** нельзя отключить или понизить: сервер отвечает 409, кнопки на экране неактивны и объясняют причину.
- **Смена роли, отключение, сброс и смена пароля отзывают сессии** пользователя. Обычные запросы отозванной сессии получают 401 сразу, открытый поток событий закрывается не позже чем через 25 секунд.
- **Защита записи** — те же слои, что у BFF: `Content-Type: application/json`, свой `Origin`, cookie `SameSite=Lax`.

Разбор — [docs/study/19](../../docs/study/19-пользователи-и-сессии.md).
