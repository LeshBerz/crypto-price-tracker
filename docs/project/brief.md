# Бриф проекта

Итоги брифинга «заказчик ↔ исполнитель» от 06.10.2026. Это источник истины по целям и границам проекта: при конфликте с другими документами прав бриф, а сам бриф меняется только по согласованию с заказчиком.

## 1. Цели и приоритеты

| Приоритет | Цель |
|---|---|
| 1 | Пройти Fast Track Evercode Lab: сервис, который **буквально** соответствует ТЗ (см. [requirements.md](requirements.md)) |
| 2 | Проект для портфолио фуллстек-разработчика: продуманная архитектура, фронтенд, инфраструктура |
| 3 | Подготовка к собеседованию: каждое решение обосновано и защищаемо |

- Срок — 7 дней (до 12.10.2026), в день 6+ часов.
- **API-first.** День 1 целиком уходит на анализ и проектирование: архитектура, модель данных, контракт API, ADR. Кода в этот день нет. Цель — ничего потом не переписывать.

## 2. Стратегия: две редакции в одном монорепо

| Часть | Что это | Ограничения |
|---|---|---|
| `apps/api` | **Сдаваемая версия.** Express + TS + SQLite (raw SQL) | **Строго ТЗ**: только разрешённые библиотеки и стандартные модули Node. Архитектура на портах и адаптерах (`EventBus`, `PriceCache`, `Notifier`, репозитории) |
| `apps/web` | Дашборд и панель оператора | Отдельное приложение-бонус, на сдачу не влияет |
| профиль `platform` | Портфолио-редакция: те же порты, адаптеры на Redis, RabbitMQ, отдельный воркер, другие БД | Включается через `docker compose --profile platform`. На поведение `apps/api` по умолчанию не влияет |

Почему так: ТЗ запрещает сторонние БД и библиотеки, а «внимательность к требованиям» — критерий оценки. MSA для одного домена — оверинжиниринг. Поэтому сдаём ТЗ без отступлений, а масштабирование показываем рядом: явно, опционально и с обоснованием в документе «Целевая архитектура и путь миграции».

Референс уровня проработки — прошлый проект заказчика **Korefan** (MSA, RabbitMQ + DLQ, Redis, database-per-service, k8s, CI/CD, IaC). Отчёт лежит в `../Контекст/`.

## 3. Продукт

### Роли
- **Viewer** — смотрит дашборд.
- **Operator** — управляет монетами, синхронизацией и алертами.
- Модель доступа (API key со scope, пользователи + JWT или BFF) — **решаем в аналитике**, ADR.

### Функциональность
| Блок | Состав | Источник |
|---|---|---|
| Watchlist | CRUD отслеживаемых монет, проверка символа в CMC | ТЗ |
| Цены | Актуальные цены, единая валюта (USD) | ТЗ |
| История и агрегаты | История за период, интервалы (1h / 1d …), min / max / avg, % изменения | ТЗ («агрегация») + расширение |
| Синхронизация | Фоновое обновление, таймауты, retry, деградация при падении CMC | ТЗ |
| Мониторинг | История запусков задач, ошибки, ручной запуск, состояние CMC и квот | Расширение (панель оператора) |
| Realtime | Обновление цен и алертов без перезагрузки (SSE) | Расширение |
| Алерты | Правила вида «BTC < X», «изменение > N%». Каналы доставки: дашборд (SSE), Telegram-бот, webhook с HMAC-подписью, email | Расширение |

> Каналы алертов — тоже через порт `Notifier`. В `apps/api` разрешены только каналы, реализуемые на axios и `node:crypto` (Telegram Bot API, webhook). Email без сторонних библиотек — вопрос для ADR (HTTP API провайдера или только в `platform`).

## 4. Нефункциональные требования
- Документация **на русском**.
- Запуск **локально**: `docker compose up`. Деплоя нет. IaC (Terraform, Ansible) — в самую последнюю очередь, опционально.
- CI на GitHub Actions: lint, typecheck, тесты, coverage.
- Conventional commits + git hooks.
- Observability: структурные логи с requestId, liveness и readiness, метрики.
- ADR на каждое значимое решение — `docs/adr/`.
- В репозитории **нет подписей AI-инструментов** (Co-Authored-By и т. п.).
