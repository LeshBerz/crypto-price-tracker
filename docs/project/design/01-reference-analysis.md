## 1. Зачем и как

Web — бонус (бриф §2), но это витрина для портфолио. Задача — не изобрести интерфейс, а взять у зрелых продуктов то, что подходит **масштабу проекта**: до 100 монет, синхронизация раз в 5 минут, две роли, ни одной торговой функции.

### Что есть на самом деле

Отправная точка — контракт, а не референсы. Красиво нарисовать то, чего нет в API, легко, но защищать потом нечего.

| Данные | Операция | Особенность для UI |
|---|---|---|
| Цена, `change24hPercent`, `isStale`, `fetchedAt`, `sourceUpdatedAt` | `listLatestPrices` | цена — строка (ADR 0006); `latest: null` до первой синхронизации; `change24hPercent: null`, если истории меньше суток |
| `lastSync` (`id`, `status`, `finishedAt`) | `listLatestPrices` | статусы `running / succeeded / partial / failed / interrupted` |
| Мини-графики 24 ч (24 точки) и 7 д (42 точки) | `listSparklines` | один запрос на весь watchlist |
| OHLC-бакеты `1h / 4h / 1d / 1w`, сводка, `points` | `getPriceAggregates` | ≤ 1000 бакетов; пустые бакеты не выдумываются |
| Сырые точки | `listPriceHistory` | курсорная пагинация |
| Запуски синхронизации | `listSyncRuns`, `triggerSyncRun`, `getSyncRun` | `202 + Location`, `409` с `conflictingId` |
| CMC: последний успех и ошибка, квота | `getCmcStatus` | `quota: null`, пока `key/info` не получен |
| Realtime | `streamEvents` (SSE через BFF) | `price.updated`, `sync.finished`, `watchlist.changed`, `heartbeat`; пропущенное не досылается |

**Чего в контракте нет** (найдено при анализе, см. [§5](#5-влияние-на-adr) и [ADR 0017](../../adr/0017-web-ui-data-gaps.md)):
- интервала синхронизации и времени следующего запуска. Без них не построить «следующая ≈ 14:05» (ui-flows §3.2, §3.6) и прогноз квоты (§3.7);
- признака паузы в `listLatestPrices`. Без него дашборд не отличит «монета на паузе» от «CMC лежит»: в обоих случаях цена станет `isStale`.

## 2. Референсы

Для каждого — какие экраны проекта он помогает решить:
- **Л** — список цен;
- **К** — карточка монеты с графиком;
- **С** — свежесть данных;
- **Д** — деградация при сбое источника;
- **О** — операторские действия.

### 2.1 CoinMarketCap — эталон списка цен (Л, К)

**Что видно (проверено).** Колонки главной таблицы: `#`, Name, Price, 1h %, 24h %, 7d %, Market Cap, Volume (24h), Circulating Supply, Sentiment, график 7 дней. Над таблицей — вкладки (Top, Trending, Watchlist, Gainers…), фильтры и кнопка «Columns». Мелкие цены — обычные десятичные с ведущими нулями: `$0.00000000028225`. Вместо метки времени — фраза о том, что цена обновляется в реальном времени.

| Подходит проекту | Не подходит |
|---|---|
| Символ и название в одной ячейке, цена и проценты справа. Это привычная «грамматика» крипто-таблицы — пользователю не надо учиться | 11 колонок, капитализация, объём, предложение. **Этих данных в проекте нет** (CMC Basic, ADR 0007), и рисовать их не будем |
| Спарклайн в последней колонке — быстрый ответ на вопрос «куда идёт» | Свежесть не видна: «real-time» без времени. Здесь синхронизация раз в 5 минут, и **честное время — преимущество**, а не слабость |
| Знак у процента и цвет — направление считывается сразу | Реклама, баннеры, вкладки категорий — шум для watchlist из 5–20 монет |

**Берём:** порядок колонок «монета → цена → 24 ч → график», цену и проценты по правому краю, спарклайн в строке.

### 2.2 CoinGecko — карточка монеты и сводка (К) — **не проверено**

Страница не открылась (домен заблокирован для WebFetch). По памяти: на карточке есть график с переключателем «цена / капитализация» и «линия / свечи», периоды 24h / 7d / 1m / 3m / 1y / Max, рядом блок статистики (диапазон 24 ч, исторические максимум и минимум).

| Подходит проекту | Не подходит |
|---|---|
| Два переключателя у графика: **вид** (линия / свечи) и **период**. Здесь они ложатся на `interval` и `from` в `getPriceAggregates` | Капитализация, ATH/ATL, конвертер. Таких данных нет |
| Статистика периода — отдельным блоком рядом с графиком. Аналог — `summary` (open / close / min / max / avg / изменение / точек) | Длинная лента новостей и описаний на той же странице |

**Берём:** сводку периода отдельным блоком; переключатели вида и периода над графиком.

### 2.3 TradingView и Lightweight Charts — график (К, С)

**Проверено.** Лицензия Lightweight Charts требует указать TradingView как автора: текст из `NOTICE` и ссылка на tradingview.com на публичной странице приложения. Для realtime документация советует `series.update()` (обновляет последнюю точку или добавляет новую), а не `setData`. Актуальная версия документации — 5.2. Отдельно: TradingView помечает символы с задержанными данными буквой **«D»** рядом с названием.

| Подходит проекту | Не подходит |
|---|---|
| Свечи плюс crosshair с OHLC в легенде: наведение на свечу показывает open / high / low / close. Это ровно `PriceBucket` | Полный терминал: индикаторы, рисование, мульти-графики, стакан. Это Advanced Charts, вне задач проекта |
| **Метка задержки «D» у символа** — компактный и честный способ сказать «данные не реального времени». Аналог — `isStale` | Плотность и мелкий шрифт панелей рассчитаны на трейдера за большим монитором |
| `series.update()` для тика — свеча меняется без перерисовки всего графика | Вкладки таймфреймов 1m / 5m / 15m — минимальный интервал здесь 1 ч (ADR 0007) |

**Берём:** свечи и линию из Lightweight Charts (ADR 0012), OHLC в легенде по crosshair, метку состояния у символа по образцу «D».

### 2.4 Binance (страница цены) — формат и честность (Л, К, С)

**Проверено.** Мелкая цена — обычные десятичные: `$0.0000041`. Для совсем малых сумм — `$<0.000001`. Изменение — проценты со знаком: `-4.22%`, `+29.48%`. Периоды основного графика — 1D, 7D, 1M, 3M, 1Y, YTD. Внизу — «Page last updated: … (UTC)» и оговорка, что информация справочная. Цвета роста и падения (зелёный `#0ecb81`, красный `#f6465d`) известны из стороннего разбора дизайн-системы ([shadcn.io](https://www.shadcn.io/design/binance/raw)), официально **не проверено**.

| Подходит проекту | Не подходит |
|---|---|
| Явное время обновления страницы в UTC. Здесь это `fetchedAt` в подсказке | Кнопки «Купить», торговые пары, промо. Торговли в проекте нет |
| Знак `+`/`−` у процента всегда, а не только у отрицательных | `$<0.000001` скрывает реальную цену. Точность — принцип проекта (ADR 0006), поэтому цифры показываются |
| Цвет роста и падения применяется **к тексту**, а не к фону карточек | Плотная тёмная тема с жёлтым акцентом — узнаваемый бренд, копировать не нужно |

**Берём:** знак всегда, цвет только на тексте и мелких метках, время обновления в UTC в подсказке.

### 2.5 Coinbase — спокойный стиль (Л, К) — **частично не проверено**

Страница цены вернула 403. Проверено только одно: Coinbase в октябре 2025 открыла дизайн-систему **CDS** — React и React Native, темизация через `ThemeProvider` со светлой и тёмной темой ([документация CDS](https://cds.coinbase.com/getting-started/introduction)). Остальное — по памяти: много воздуха, крупная цена в шапке карточки, периоды 1H / 1D / 1W / 1M / 1Y / ALL под графиком, линия вместо свечей для розничного пользователя.

| Подходит проекту | Не подходит |
|---|---|
| Светлая и тёмная тема **на равных**: светлая не выглядит «второсортной» | Линия по умолчанию для розницы. Данные проекта — OHLC-бакеты, поэтому свечи по умолчанию, линия — переключателем |
| Крупная цена и изменение в шапке карточки, подробности ниже | Маркетинговые блоки, «Learn & earn» |
| Сдержанная палитра: акцент один, цвета роста и падения — только для данных | — |

**Берём:** иерархию шапки карточки (символ → крупная цена → изменение), равноправные темы.

### 2.6 Grafana — мониторинг (С, Д, О)

**Проверено** ([best practices](https://grafana.com/docs/grafana/latest/dashboards/build-dashboards/best-practices/)): дашборд должен отвечать на вопрос и идти от общего к частному; «dashboards should reduce cognitive load»; цвет — со смыслом (пороги «норма / проблема»); частота обновления — по частоте изменения данных; описания у панелей.

| Подходит проекту | Не подходит |
|---|---|
| **От общего к частному**: сверху «всё ли хорошо?» (состояние CMC, последний запуск), ниже детали (таблица запусков, ошибки) | Конструктор панелей, запросы, переменные. Панель оператора фиксирована |
| Пороги цветом **и текстом**: квота CMC < 20 % — предупреждение | Графики метрик ради графиков. Здесь 5–6 чисел, им хватит карточек |
| Частота обновления = частоте данных. Синхронизация раз в 5 минут, поэтому опрашивать каждую секунду незачем. Тем более есть SSE | Тёмная «ночная» эстетика NOC — не аудитория проекта |

**Берём:** экран «Система» как сверху вниз «итог → детали»; пороги цветом с текстовым статусом; пояснение под каждой метрикой.

### 2.7 Stripe Workbench и Vercel — операторские действия (О)

**Проверено.** Stripe: у доставки вебхука статусы Delivered / Pending / Failed. По клику — история попыток с HTTP-кодом каждой и временем следующего ретрая; ручной повтор доступен прямо из списка. Vercel: у деплоя видны время сборки, логи и ошибки; действия Redeploy и Inspect — рядом с объектом.

| Подходит проекту | Не подходит |
|---|---|
| **Запуск = строка с историей попыток.** `SyncRun` уже содержит `attempts`, `error.code`, `error.message` — показываем так же | Много уровней вложенности (проект → деплой → функция). Здесь один уровень: запуск |
| Действие рядом с объектом: «Синхронизировать сейчас» рядом со статусом последнего запуска | Ретрай отдельного события: запуск синхронизации атомарный, повторять можно только целиком |
| Статус — **словом и цветом**, с моноширинным кодом ошибки и id запроса для поддержки | — |

**Берём:** таблицу запусков в стиле «доставок» Stripe (статус-бейдж, попытки, код ошибки, `requestId` в деталях); действие рядом со статусом.

## 3. Сквозные темы

### 3.1 Свежесть и деградация

Референсы делятся на два лагеря. Агрегаторы (CMC) скрывают время за словами «real-time». Биржи и TradingView показывают его явно: «Page last updated», метка «D». Сервис синхронизируется раз в 5 минут, поэтому **время данных — первичная информация**, а не мелкий шрифт.

Модель состояний строится только из полей контракта:

| Состояние | Как определяем | Где видно | Визуал |
|---|---|---|---|
| Свежо | `isStale = false`, `lastSync.status = succeeded` | колонка «Обновлено» | «2 мин назад», подсказка — `fetchedAt` в UTC |
| Синхронизация не удалась, но цены ещё свежие | `lastSync.status ∈ {failed, interrupted}`, `isStale = false` у всех | тонкая информационная строка над таблицей | «Последняя синхронизация 14:05 не удалась (CMC_TIMEOUT). Цены пока актуальны» |
| Частичная синхронизация | `lastSync.status = partial` | та же строка | «Обновлены не все монеты» + стale-метки у отставших |
| **Деградация CMC** | `isStale = true` хотя бы у одной активной монеты | **баннер** `role="status"` над таблицей + метка ⚠ у цены | «Цены устарели: CoinMarketCap недоступен. Последнее успешное обновление — 13:50». Начала сбоя в контракте нет, а максимум `fetchedAt` есть. Цена — приглушённым цветом **и** значком ⚠ с текстом «устарела» |
| Нет данных | `latest = null` | ячейка цены | «ожидает первой синхронизации» |
| На паузе | `isPaused = true` (см. [ADR 0017](../../adr/0017-web-ui-data-gaps.md)) | метка «пауза» | серая метка без ⚠: это решение оператора, а не сбой |
| Realtime оборван | `EventSource` закрыт | индикатор в шапке | ● «онлайн» / ○ «переподключение…» — **словом**, не только цветом точки |

Правила:
- **Данные не исчезают при сбое.** Цены остаются, меняется только их статус (graceful degradation, ADR 0014).
- **Баннер один и по делу**: что случилось, с какого времени, что это значит для пользователя. Оператору — ссылка «Подробнее» на `/operator/system`.
- **Порог свежести считает сервер** (`isStale`). Клиент не дублирует формулу «2 интервала», а показывает относительное время по `fetchedAt` и обновляет его раз в 30 с (ui-flows §5).

### 3.2 Точные цены, проценты, цвет

**Цены** — строки до `Intl.NumberFormat`. Он форматирует строку точно, без промежуточного `Number`: это подтверждает [MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/format), а для Node 24 — ADR 0012. Правило из ui-flows сохраняем: ≥ 1 — 2 знака после запятой, < 1 — 6 значащих цифр.

| Строка из API | В таблице | Почему |
|---|---|---|
| `67123.451234567891` | `$67,123.45` | ≥ 1 → 2 знака |
| `0.99981234` | `$0.999812` | < 1 → 6 значащих |
| `0.0000123456789` | `$0.0000`**`123457`** | ведущие нули приглушены |
| `0.0000000012345678901` | `$0.00000000`**`123457`** | там же |

Как показать мелкие цены — три варианта из практики:

| Вариант | Где встречается | Плюсы | Минусы |
|---|---|---|---|
| Обычные десятичные | CMC, Binance (проверено) | копируется и читается скринридером как число | 8 нулей трудно сосчитать глазом |
| Подстрочный счётчик нулей `0.0₈1235` | некоторые биржи; Capital.com ввёл в 2025–2026 ([справка](https://help.capital.com/hc/en-us/articles/33093412785170-Why-do-some-crypto-prices-look-different)) | компактно | при копировании получается не число; скринридер читает «ноль точка ноль восемь…»; непривычно новичку |
| **Обычные десятичные с приглушёнными ведущими нулями** | рекомендация | число остаётся числом (копирование, a11y), значащие цифры выделены | визуальная деталь требует аккуратной вёрстки |

**Рекомендация:** третий вариант. Плюс полное значение по нажатию на цену — «линза точности» (итерация 2, [README](README.md#5-изюминка--3-идеи-реализована-одна)) — и `font-variant-numeric: tabular-nums`, чтобы разряды стояли столбиком и ширина не прыгала при обновлении.

**Проценты.** В контракте — строка с 4 знаками (`-0.4012`). В таблице показываем 2 знака, знак всегда (`+1.23%`, `−0.40%`, `0.00%`), стрелку ▲/▼ и цвет. `null` → «—» с подсказкой «Истории меньше суток». Полное значение — в подсказке.

**Цвет роста и падения.** Зелёный — рост, красный — падение. Это западная конвенция и конвенция русскоязычных бирж. В Китае и Японии наоборот: красный — рост. Поэтому некоторые брокеры дают переключатель, например moomoo — «Quote Color» ([справка](https://www.moomooapp.com/us/support/topic3_41)). Для аудитории проекта переключатель не нужен.

Доступность цвета:
- **Цвет — не единственный сигнал** (WCAG 1.4.1). Всегда ещё знак `+`/`−` и стрелка ▲/▼. Красно-зелёная слепота — по часто цитируемой оценке ~8 % мужчин и ~0,4–0,5 % женщин (первоисточник в этой сессии не найден, цифры — по вторичным источникам).
- **Контраст текста ≥ 4,5:1** (WCAG 1.4.3) в обеих темах. Поэтому в светлой теме оттенки темнее, чем в тёмной: `#047857` / `#b91c1c` на белом против `#34d399` / `#f87171` на тёмном фоне. Замеры — в README.
- Свечи на графике: заливка и контур одного цвета. Направление свечи читается и по положению open/close, поэтому цвет там не единственный сигнал.

### 3.3 Тёмная и светлая тема

- ui-flows §5: «тёмная по умолчанию». Референсы расходятся (по памяти, **не проверено**): у Binance и TradingView привычна тёмная тема, у CoinGecko, CMC и Coinbase — светлая с переключателем.
- **Предложение:** по умолчанию — **системная** (`prefers-color-scheme`), переключатель «Светлая / Тёмная / Как в системе» запоминается. Это уважает настройку пользователя, а тёмная тема у крипто-аудитории и так обычно включена в ОС. Отступление от ui-flows утверждено — **решение Q1** в [README](README.md#принятые-решения).
- Обе темы проектируем **на равных токенах** (как в shadcn: `--background`, `--foreground`, `--muted`, `--border`, `--primary` + доменные `--up`, `--down`, `--stale`, `--warn`). Тогда тема — это подмена значений, а не второй набор стилей.

### 3.4 Realtime без «мигания»

Специфика проекта: цены приходят **пачкой раз в 5 минут** (`price.updated` по каждой монете после синхронизации), а не потоком тиков, как на бирже. Значит, главный риск — не «ёлка» от частых тиков, а **вспышка всей таблицы разом** каждые 5 минут.

| Приём | Откуда | Как в проекте |
|---|---|---|
| Подсветка только изменившейся ячейки, а не строки | биржевые стаканы | Мягкий тон фона ячейки цены **в цвет направления**, 1 с затухания. Если цена не изменилась — подсветки нет |
| Стабильная геометрия | TradingView, Binance | `tabular-nums`, фиксированная ширина колонок, порядок строк **не меняется** от новых данных (сортирует только пользователь) |
| Без перерисовки графика | Lightweight Charts | `series.update()` последней свечи, а не `setData` (рекомендация документации) |
| Уважение к настройкам | WCAG 2.3.3 (AAA), `prefers-reduced-motion` | При `reduce` — никакой анимации, только смена текста |
| Тишина для скринридера | WCAG 4.1.3 | Тики **не** объявляются. `aria-live="polite"` — только для тостов и смены состояния баннера (ui-flows §5) |
| Пересчёт производных | — | `change24hPercent` и `isStale` в `price.updated` не приходят. После `sync.finished` — один `invalidate(['prices'])`, чтобы сервер их пересчитал. Клиент формулы не дублирует |

### 3.5 Доступность (WCAG 2.2 AA)

| Критерий | Требование | Решение |
|---|---|---|
| 1.4.1 Use of Color | цвет — не единственный способ | знак и стрелка у процентов; ⚠ и слово «устарела» у stale-цены; статус запуска — словом |
| 1.4.3 Contrast (Minimum) | текст ≥ 4,5:1, крупный ≥ 3:1 | все пары токенов замерены (README) |
| 1.4.11 Non-text Contrast | элементы UI и значимая графика ≥ 3:1 | рамки полей ввода, фокус, линии спарклайнов, прогресс-бар квоты |
| 1.4.10 Reflow | без горизонтальной прокрутки на 320 CSS px | на телефоне таблица перестраивается в карточки; второстепенные колонки скрываются |
| 2.4.7 Focus Visible / 2.4.11 Focus Not Obscured | фокус виден и не перекрыт | кольцо фокуса 2 px `--ring` с отступом; шапка не `sticky` поверх фокуса на мобильных |
| 2.5.8 Target Size (Minimum) | цель ≥ 24×24 CSS px (по памяти, см. §1) | кнопки ≥ 36 px, переключатели интервалов ≥ 32 px |
| 2.2.2 Pause, Stop, Hide | движение > 5 с можно остановить | бесконечных анимаций нет; спиннер запуска — только пока статус `running` |
| 4.1.3 Status Messages | статусы объявляются без переноса фокуса | тосты и баннер — `role="status"` / `aria-live="polite"`; ошибки формы — `role="alert"` у поля |
| Клавиатура | всё доступно с клавиатуры | символ в строке — настоящая ссылка `<a>` (не `onclick` на `<tr>`); переключатели интервала — группа кнопок с `aria-pressed`; диалоги — с ловушкой фокуса (даст Base UI) |
| Альтернатива графику | — | canvas недоступен скринридеру. Сводка и таблица истории под графиком служат текстовой альтернативой, у графика — `aria-label` с периодом и изменением |

| Торговые кнопки, промо, новости | Binance, Coinbase, CoinGecko | ❌ | торговли нет, это шум |

### Принципы дизайна продукта

1. **Честность данных важнее эффектности.** У каждой цены видно время. Устаревшая цена помечена, а не спрятана. Пустой бакет — пропуск, а не интерполяция.
2. **Ничего не рисуем сверх контракта.** Каждый элемент экрана питает конкретная операция API (карта — в README). Нет данных — нет колонки.
3. **Точность до пикселя.** Цена — строка до `Intl.NumberFormat`, полное значение — в подсказке, ведущие нули приглушены. `Number()` — только на входе в canvas.
4. **Никогда только цветом.** Знак, стрелка, слово, значок — вместе с цветом. Контраст ≥ 4,5:1 в обеих темах.
5. **Спокойный realtime.** Без вспышек всей таблицы и без прыжков вёрстки. Подсветка изменившейся ячейки ≤ 1 с; при `prefers-reduced-motion` — без анимации.
6. **Деградация видна, но не пугает.** Один баннер: что случилось, с какого времени, что делать. Данные остаются на экране.
7. **Действие рядом с объектом, последствия до клика.** «Синхронизировать сейчас» — у статуса запуска. «Удалить» — с диалогом, числом точек истории и вводом символа.
8. **Ошибка — с адресом.** `title`/`detail` из Problem плюс `requestId` с кнопкой «Скопировать». Стеков и внутренностей нет.
9. **Мобильный — не урезанный.** На 320 px таблица становится карточками, но все статусы и действия остаются.

## 5. Влияние на ADR

**ADR 0012 менять не нужно.** Аналитика его подтверждает:
- Lightweight Charts — стандарт свечей и `series.update()`; лицензию соблюдаем атрибуцией на графике и в футере;
- shadcn/ui на токенах CSS-переменных ложится на равноправные темы;
- свой SVG для спарклайнов достаточен: в строке нужна полоска из 24–42 точек без осей и интерактива;
- `Intl.NumberFormat` со строкой подтверждён MDN.

**Найдены пробелы контракта** — оформлены как [ADR 0017](../../adr/0017-web-ui-data-gaps.md) (`Proposed`):
1. расписание синхронизации (интервал, следующий запуск) для ui-flows §3.2, §3.6, §3.7;
2. признак паузы монеты на дашборде.

**Уточнения ui-flows** (тема по умолчанию, локаль чисел, мелкие цены, пересчёт после `sync.finished`) — это не ADR, а UX-детали. Они собраны в [принятых решениях README](README.md#принятые-решения).

## 6. Что не удалось проверить

- **CoinGecko** — страницы не открылись (домен заблокирован для WebFetch). Описание по памяти.
- **Coinbase** — страница цены отдала 403. Проверено только существование и назначение CDS.
- **Цвета Binance** — из стороннего разбора, не из официального источника.
- **WCAG 2.5.8 и 4.1.3** — формулировки по памяти: эти разделы не попали в выдержку.
- **Статистика дальтонизма** — вторичные источники, первоисточник не найден.
- **Скриншоты референсов** не делались. Сравнение — по тексту страниц и документации, без визуальной сверки.
