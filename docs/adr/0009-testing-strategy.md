# 0009. Стратегия тестов: api, web, platform

- **Статус:** Accepted (06.10.2026)
- **Дата:** 06.10.2026
- **Вопрос брифа:** Q12 (в requirements — открытое решение D9)
- **Требования:** C6, C8, C9, F7; бриф §4 (CI: тесты и coverage)
- **Связано:** [0004 — tooling](0004-c7-interpretation-and-dev-tooling.md), [0005 — пакеты](0005-monorepo-structure.md), [0007 — свёртки](0007-aggregates-and-rollups.md), [0008 — контракт](0008-validation-and-openapi.md)

## Контекст

Что требует ТЗ:
- **C8** — каждый эндпоинт покрыт минимум одним позитивным и одним негативным тестом;
- **C9** — тесты на фоновые задачи и на ошибки внешнего API;
- **C6** — корректная остановка по SIGINT/SIGTERM;
- стек — Jest + Supertest.

Принцип курса («Контроль качества»): **внешние API мокаем, БД — нет**. Проверяем цепочку от запроса до результата.

### Проверено руками (Node 24.21, Jest 30)

| Проверка | Результат | Следствие |
|---|---|---|
| `jest.useFakeTimers()` + глобальный `setTimeout` | ✅ подменяется | — |
| `jest.useFakeTimers()` + `setTimeout` из `node:timers/promises` | ❌ **не подменяется** | Время и ожидания идут через порт `Clock`, а не через прямые импорты таймеров |
| Заглушка CMC на `node:http` + axios `timeout: 200` | ✅ настоящий `ECONNABORTED` через ~220 мс | Таймауты проверяются по-настоящему, без моков axios |
| Заглушка отвечает 429 + `Retry-After` | ✅ axios видит статус и заголовок | Можно честно тестировать rate limit |
| `child.kill('SIGTERM')` на Windows | ❌ процесс убит, **обработчик не вызван** | e2e-тест сигналов — только на Linux (CI, Docker) |

## Варианты (ключевые развилки)

| Развилка | Варианты |
|---|---|
| Как подменить CMC | а) `jest.mock('axios')` · б) `nock` (devDep) · в) **своя заглушка на `node:http`** · г) только фейк порта `CmcClient` |
| БД в тестах | а) моки репозиториев · б) **настоящая SQLite `:memory:` + миграции на каждый тест** · в) общий файл БД |
| Время | а) реальные таймеры · б) только fake timers Jest · в) **порт `Clock` + fake timers** |
| Как доказать C8 | а) вручную, по чек-листу · б) **автоматически: матрица `operationId × {позитивный, негативный}` из отчёта Jest** |
| Тесты адаптеров `platform` | а) моки Redis/RabbitMQ · б) **Testcontainers + общий контрактный набор тестов для порта** |

### Почему не моки axios и не nock

| Критерий | `jest.mock('axios')` | nock | Заглушка на `node:http` |
|---|---|---|---|
| Проверяет реальный таймаут axios | ❌ | 🟡 эмулирует | ✅ настоящий сокет |
| Проверяет `transformResponse` проекта с `context.source` (ADR 0006) | ❌ мок возвращает уже распарсенный объект | ✅ | ✅ |
| Зависимости | 0 | +1 devDep, патчит `http` глобально | 0 |
| Переиспользование | только в Jest | только в Node-процессе | ✅ тот же стаб — контейнер `cmc-stub` для e2e и демо без ключа |

## Решение (рекомендация)

### `apps/api` (сдаваемая версия): Jest + Supertest

**Слои тестов**

| Слой | Что | Как | Примеры |
|---|---|---|---|
| Unit | Чистая логика | Без БД и сети | `Decimal` (ADR 0006), валидатор схем (ADR 0008), backoff + jitter, бакетизация недель «с понедельника», `config` |
| Интеграционные HTTP | Каждый эндпоинт целиком | `createApp(deps)` + Supertest + **реальная SQLite `:memory:`** с миграциями, свежая на каждый тест (миллисекунды). Внешний мир — фейки портов | C8: позитивные и негативные кейсы, 401/403 по scope, 400/409/413/415/422, `toMatchContract` |
| Интеграционные CMC | HTTP-клиент CMC | **Заглушка на `node:http`** на случайном порту, сценарии: 200, 429 + `Retry-After`, 500, 401 (неверный ключ), обрыв соединения, таймаут, невалидный JSON, неизвестный символ | C5, C9, F7 |
| Фоновые задачи | Планировщик и синхронизация | Порт `Clock` + fake timers. Проверяем: нет наложения запусков (D10), ретраи, деградация при падении CMC (старые цены остаются, запуск помечен `failed`), пересчёт свёрток идемпотентен | C9, ADR 0007 |
| Shutdown | Остановка | **Unit:** координатор останавливает таймеры, ждёт текущую синхронизацию, закрывает сервер и БД (сигнал передаём через внедрённый эмиттер). **E2e на Linux:** реальный процесс, `SIGTERM` → код выхода 0, в логе «shutdown complete», без незавершённой транзакции | C6 |

**Правила**
- **Изоляция.** Ни одного общего состояния между тестами. Каждый тест получает свою БД и свой `Clock`. Тесты параллельны по файлам.
- **БД не мокаем** (курс). Репозитории тестируются только через настоящую SQLite. Отдельно проверяем правило ADR 0007 «integer-параметры — BigInt».
- **Время детерминировано.** `FakeClock` с фиксированным `now()`. Никаких `Date.now()` и `sleep` в логике в обход порта: правило ESLint `no-restricted-syntax` / `no-restricted-imports`.
- **Сеть закрыта.** Тесты не ходят в реальный CMC. Настоящий ключ используется только в ручном скрипте `npm run smoke:cmc`: он проверяет формат ответа (риск из ADR 0006) и не входит в CI.
- **Контракт.** Каждый HTTP-тест проверяет ответ через `toMatchContract(operationId, status)` (ADR 0008).

**Доказательство C8 — автоматическое**
- **Имена тестов:** `describe('[createCryptocurrency] POST /api/v1/cryptocurrencies')`, кейсы `it('✅ …')` и `it('❌ …')`.
- **Скрипт `check-endpoint-coverage`:** читает `jest --json` и спеку, для каждого `operationId` требует ≥1 пройденный ✅ и ≥1 пройденный ❌. Иначе CI красный.
- **Отчёт:** скрипт генерирует матрицу `docs/project/test-matrix.md` для README и проверяющего.

**Coverage (пороги в `jest.config`, CI падает при нарушении)**

| Область | Lines | Branches |
|---|---|---|
| Глобально `apps/api/src` | 90 % | 85 % |
| `Decimal`, валидатор, auth-middleware | 100 % | 100 % |

Coverage — это сигнал, а не цель. Критичные модули доводим до 100 % ради граничных случаев, а не ради цифры.

### `apps/web` (бонус)

| Слой | Инструмент | Что |
|---|---|---|
| Unit | Jest (`next/jest`) — один раннер на весь репозиторий | BFF Route Handlers: маппинг роли → ключ (ADR 0002), сессия, прокси SSE. Утилиты форматирования цен-строк |
| E2e | **Playwright** против `docker compose` со стабом `cmc-stub` | 3–5 сквозных сценариев: вход Viewer → дашборд; Viewer не видит операций оператора; Operator добавляет монету → цена появляется (SSE); ошибка CMC → баннер деградации |

Компонентные тесты каждого UI-элемента не пишем: для бонус-приложения за 1,5 дня e2e по критичным сценариям дают больше уверенности.

### `platform`

- **Контрактные тесты портов.** Для каждого порта (`PriceCache`, `EventBus`, репозитории) один общий набор тестов, например `describePriceCacheContract(factory)`. Его прогоняем **и** на адаптере `apps/api` (SQLite / in-process), **и** на адаптере `platform` (Redis / RabbitMQ / Postgres). Это проверяет на практике, что адаптеры взаимозаменяемы (LSP из SOLID).
- **Реальная инфраструктура в тестах — Testcontainers.** devDependency `packages/platform-adapters`, Docker на раннере GitHub Actions есть.
- **Сценарии отказов:** RabbitMQ — сообщение после N неудачных обработок уходит в DLQ (как в Korefan). Redis недоступен — сервис работает без кэша.

### CI (детали — в фазе E)

| Job | Что | Блокирует merge |
|---|---|---|
| `api` | lint, typecheck, check-deps, актуальность codegen, Jest + coverage, check-endpoint-coverage, shutdown-e2e (Linux) | ✅ |
| `web` | lint, typecheck, Jest | ✅ |
| `platform` | Testcontainers, контрактные тесты портов | ✅ |
| `e2e` | `docker compose` + `cmc-stub` + Playwright | ✅ |

### Сопутствующее: сигналы в Docker

Тест на Windows вскрыл и вторую ловушку. В контейнере команда должна быть `CMD ["node", "dist/server.js"]`, а не `npm start`: npm как PID 1 не передаёт `SIGTERM` дочернему процессу. Плюс `init: true` в compose (tini), чтобы корректно обрабатывались сигналы и зомби-процессы. Иначе C6 работает локально и ломается в Docker.

## Последствия

- ➕ C8 и C9 доказываются автоматически, а не обещаются: матрица эндпоинтов, coverage и контракт проверяются в CI на каждый коммит.
- ➕ Курс соблюдён буквально: внешний API подменяется на сетевом уровне, БД настоящая.
- ➕ Заглушка CMC работает трижды: в тестах api, в e2e и для демо без ключа CMC.
- ➕ Контрактные тесты портов — самое сильное доказательство архитектуры «порты и адаптеры».
- ➖ Порт `Clock` и внедрение зависимостей везде, где есть время. Это плата за детерминизм, и та же DI нужна архитектуре.
- ➖ Shutdown-e2e не запускается на Windows локально. Локально помогает `docker compose run`, а CI — на Linux.
- ➖ Testcontainers и Playwright медленные: отдельные jobs, кэш браузеров и образов.
- Закрывает D9 в `requirements.md`.

## Как защищать на интервью

«По курсу внешний API я мокаю, а БД — нет. Только мокаю не axios, а ставлю настоящий HTTP-стаб CMC. Так проверяются реальные таймауты, 429 с `Retry-After` и мой парсер точных цен. БД — настоящая SQLite в памяти, своя на каждый тест. Время внедряю через `Clock`, потому что fake timers Jest не подменяют `node:timers/promises`, и я это проверил. Требование «позитивный и негативный тест на эндпоинт» проверяет скрипт по спеке и отчёту Jest. Адаптеры `platform` проходят тот же контрактный набор тестов, что и адаптеры api».
