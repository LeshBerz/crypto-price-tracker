## Контекст

`apps/web` — Next.js 16 (React 19.2), бонус, ограничения C7 на него не распространяются. Время — 1,5 дня (фаза C). Экраны: дашборд (Viewer), панель оператора (watchlist, синхронизация, квоты CMC, алерты, доставки).

Что важно для выбора:

| Фактор | Следствие |
|---|---|
| Данные — OHLC-бакеты (open/close/min/max, ADR 0007) и поток цен в реальном времени (SSE) | Нужен **финансовый** график: свечи, временная шкала, инкрементальное обновление точки |
| Цены — строки с произвольной точностью, от 1e5 до 1e-9 (ADR 0006) | Форматирование без потери точности и подписи шкалы для крошечных цен |
| App Router, server components | UI-кит без runtime CSS-in-JS, иначе трение с RSC |
| 1,5 дня | Готовые доступные компоненты, минимум своей вёрстки |

### Проверено руками (Node 24.21)

| Проверка | Результат |
|---|---|
| `Intl.NumberFormat(...).format('67123.451234567891')` — **строка** | `$67,123.451234567891`: точно (ES2023, Intl.NumberFormat v3 принимает десятичные строки) |
| То же, но `Number(...)` | `$67,123.4512345679`: потеря |
| `maximumSignificantDigits: 6` для `'0.0000000012345678901234'` | `$0.00000000123457`: крошечные цены читаемы |

Вывод: свой `Decimal` в web **не нужен**. Отображение цен — `Intl.NumberFormat` со строкой на входе.

## Решение (рекомендация)

| Слой | Выбор | Почему |
|---|---|---|
| **UI-кит** | **shadcn/ui** на **Base UI** (дефолт с 07.2026) + **Tailwind CSS 4** | Нет трения с RSC. Код компонентов лежит в репозитории. Доступность от примитивов. Тёмная тема — стандарт для крипто-дашбордов |
| **Основной график** | **TradingView Lightweight Charts 5** | Свечи из OHLC-бакетов api, линия для `raw`, `series.update()` для SSE. Атрибуция — `attributionLogo: true` + ссылка в футере (требование лицензии) |
| **Мини-графики** (спарклайны в таблице watchlist) | свой SVG-компонент (~30 строк) | Второй библиотеки графиков ради полоски в строке таблицы не нужно |
| **Слой данных** | **TanStack Query 5** (82,8 млн в неделю) | Кэш запросов к BFF, мутации оператора с инвалидацией. SSE-события пишут прямо в кэш (`setQueryData`), без лишних перезапросов |
| **Форматирование цен** | `Intl.NumberFormat` со **строкой** на входе | Точно, без своего `Decimal` (проверено). Для цен < 1 — `maximumSignificantDigits` |

### Правила точности на клиенте (продолжение ADR 0006)

- В UI цены остаются **строками** вплоть до форматирования.
- `Number(price)` допустим **только** на входе в график: ADR 0006 явно разрешает float там, где пиксель грубее double.
- Шкала графика для крошечных цен — свой `priceFormatter` (значащие цифры, а не фиксированные знаки после запятой).
- Пороги алертов вводятся строкой и валидируются тем же паттерном, что в контракте (ADR 0008).

## Последствия

- ➕ Финансовый вид, свечи и realtime без компромиссов. Доменная уместность для Evercode (FinTech/Web3).
- ➕ Минимум зависимостей и одна библиотека графиков.
- ➕ Тема для интервью: Intl.NumberFormat v3 и строки, императивная обёртка над canvas-библиотекой в React (`useEffect`, cleanup, `ResizeObserver`), инвалидация кэша событиями SSE.
- ➖ Lightweight Charts императивный: нужна аккуратная React-обёртка (создание, обновление данных, удаление в cleanup, ресайз). Делаем один компонент `PriceChart`.
- ➖ Обязательная атрибуция TradingView: логотип на графике и ссылка в футере. Это требование лицензии, фиксируем в README.
- ➖ shadcn копирует код в репозиторий: обновления компонентов — вручную, через CLI.
- Открыто до UI-флоу: перечень экранов и компонентов.

## Поправки (реализация C4, 12.10)

Решения 6, 7 и 9 утверждены 12.10.2026 до начала реализации; 8 и 10 — уточнения, найденные при реализации.

| # | Решение | Почему |
|---|---|---|
| 6 | Правило «цены — строки» на карточке монеты: `Number()` — только в [`chart-data.ts`](../../apps/web/src/lib/coin/chart-data.ts), на входе в график. Деления шкалы цен подписывает библиотека из `number` (`formatAxisPrice`). Всё, что вне canvas, берётся из строк api: подсказка под курсором (значения бакета находятся по времени), сводка, шапка, таблица истории | Деление шкалы — округлённая координата, исходной строки у него нет. Значение под курсором — наблюдённая цена: её показывает React из ответа api, а не график из float. Отдельная поправка к ADR 0006 не нужна: исключение для пикселей там уже записано |
| 7 | Поток событий — один на вкладку: `StreamProvider` в layout группы `(app)`. События пишутся в кэш запросов; экраны читают кэш, подписчиков на поток у них нет | Переход дашборд ↔ карточка не переоткрывает соединение, `session.expired` действует на любом экране. Вариант «свой `EventSource` на каждой странице» давал переподключение на каждый переход и два места с логикой повторов |
| 8 | Следствие п. 7: фоновый перезапрос уходит только за данными, которые сейчас на экране (у запроса есть наблюдатель). Остальное помечается устаревшим и перечитывается при открытии экрана. Если поток отказал, а запросов на экране нет, — один запрос цен как проба причины (401 → страница входа) | Иначе карточка монеты каждые 5 минут запрашивала бы цены и мини-графики дашборда, которого на экране нет |
| 9 | Данные для проверки графика — dev-скрипт [`seed-price-history.ts`](../../apps/web/scripts/seed-price-history.ts): случайное блуждание цены перед самой ранней точкой каждой монеты, затем `rollups:rebuild`. В образ и CI не входит. Логика — на подставных данных в Jest | Стаб CoinMarketCap отдаёт неизменную котировку, тариф Basic не отдаёт историю. Менять стаб нельзя: им пользуются smoke и CI сдаваемого сервиса. Цена решения: скрипт знает схему `price_history` |
| 10 | Шкала времени графика и время бакета в подсказке — UTC (с пометкой на экране). История и шапка — в часовом поясе браузера | Бакеты api выровнены по UTC: дневная свеча в локальном времени начиналась бы, например, в 03:00. Сдвиг меток времени под пояс даёт дубли времени при переводе часов, а график на дублях падает |

Отклонение от текста решения: атрибуция — `attributionLogo: true` и ссылка в подвале, как и записано; отдельная React-обёртка `PriceChart` одна, как и планировалось.

## Поправки (реализация C5, 12.10)

Решения 11–13 утверждены 12.10.2026 до начала реализации; 14–16 — уточнения, найденные при реализации.

| # | Решение | Почему |
|---|---|---|
| 11 | Результат мутации записывается в кэш запросов **из ответа api** (`applyCoinSaved`, `applyCoinDeleted`, `upsertRun`). Обновление не оптимистичное: до ответа экран не меняется. Событие `watchlist.changed` для своей вкладки не обязательно | Поток событий может быть отключён — экран после сохранения не должен зависеть от него. Оптимистичный вариант требует отката, а результат добавления непредсказуем: имя и CMC ID выбирает сервис, возможны 409, 422 и 503. Правило ui-flows §5 «без оптимистичных обновлений» сохраняется |
| 12 | Диалог и уведомления — обёртки над уже установленным `@base-ui/react` (`Dialog`, `Toast`): [`ui/dialog.tsx`](../../apps/web/src/components/ui/dialog.tsx), [`ui/toast.tsx`](../../apps/web/src/components/ui/toast.tsx). **Новых зависимостей нет** | В Base UI 1.9.0 оба компонента есть; `sonner` дал бы +1 runtime-зависимость ради того же поведения |
| 13 | Пока api отдаёт контракт `1.0.0`, «следующий запуск», «расписание» и прогноз квоты не показываются. Блок `schedule` читается из ответа с проверкой формы (`readSchedule`): появился в ответе — появился на экране, без изменения кода web | Сдаваемый api не меняется до проверки ([ADR 0017](0017-web-ui-data-gaps.md); поправка к ADR 0014 с контрактом `1.1.0` — в ветке `feat/api-sync-schedule`). Оценивать расписание на клиенте нельзя: это второй источник правды |
| 14 | Разделы оператора — отдельные адреса (`/operator/watchlist`, `/operator/sync`, `/operator/system`) с общим layout, а не вкладки по `#hash`, как в макете | Роль проверяется в серверном layout до отдачи разметки; `#hash` на сервер не приходит. Данные экрана «Система» перечитываются по `sync.finished` и кнопкой «Обновить», опроса по таймеру нет | Экран должен показать, какая проверка не прошла. Таймер продлевал бы сессию или требовал бы признака фона у каждого тика ([ADR 0016](0016-web-auth-and-bff-routes.md), поправка 26) |

- В диалоге удаления нет числа точек истории («12 480 точек»): в контракте такого поля нет. Текст — «вся история цен». Поле в api — кандидат на отдельное решение (см. [ADR 0017](0017-web-ui-data-gaps.md#найдено-при-реализации-c5-12102026)).

## Как защищать на интервью

«Данные у меня — OHLC-бакеты плюс поток цен, поэтому взял финансовый график TradingView Lightweight Charts. У Recharts нет свечей, а перерисовывать весь SVG на каждый тик дорого. UI — shadcn на Base UI и Tailwind: с App Router нет трения, код компонентов принадлежит проекту. Цены до самого экрана остаются строками: Intl.NumberFormat умеет форматировать десятичную строку без потери точности. В число я их превращаю только для canvas графика, где точности пикселя достаточно».
