# 0003. Драйвер SQLite и версия Node.js

- **Статус:** Accepted (06.10.2026)
- **Дата:** 06.10.2026
- **Вопрос брифа:** Q3 (в requirements — открытое решение D1)
- **Требования:** C1, C2, C7, стек «Node.js 18+», «SQLite (без ORM)»

## Контекст

- C7: «можно использовать только указанные библиотеки и стандартные возможности Node.js». В стеке указан «SQLite», но **драйвера** в списке нет. А чтобы работать с SQLite из Node, драйвер нужен.
- C1: только raw SQL, без ORM и query builder.
- Стек: «Node.js 18+». Это нижняя граница, а не точная версия.
- Состояние Node на 06.10.2026 (по [nodejs/Release](https://github.com/nodejs/Release)):

| Версия | Статус | Конец поддержки |
|---|---|---|
| 18, 20 | **End-of-Life** (апрель 2025 и апрель 2026) | — |
| 22 | Maintenance LTS | 30.04.2027 |
| **24** | **Active LTS** (до 20.10.2026, потом maintenance) | 30.04.2028 |
| 26 | Current, станет LTS 28.10.2026 — **после** дедлайна проекта | 30.04.2029 |

- Статус встроенного модуля `node:sqlite` ([docs v24](https://github.com/nodejs/node/blob/v24.x/doc/api/sqlite.md)):
  - добавлен в v22.5.0 за флагом;
  - с v22.13.0 работает без флага, но остаётся *experimental*;
  - с **v24.15.0** (и v25.7.0) — **Stability 1.2 Release candidate**.

### Проверено руками (06.10.2026)

| Проверка | Результат |
|---|---|
| Node 22.23.2 (локально) | работает, но печатает `ExperimentalWarning: SQLite is an experimental feature` |
| Node 24.21.0 (`node:24-alpine`) | работает **без предупреждений**, SQLite 3.53.4, `PRAGMA foreign_keys` = 1 по умолчанию |
| Jest 30.5 + `node:sqlite` | тест проходит: prepared statements, `ON DELETE CASCADE`, ошибка `NOT NULL` ловится |

## Варианты

1. **`node:sqlite` на Node 24 LTS** — встроенный модуль, ноль зависимостей.
2. **`better-sqlite3`** — самый популярный драйвер, около 6,9 млн скачиваний в неделю ([socket.dev](https://socket.dev/npm/package/better-sqlite3/overview/12.10.1)). Нативный аддон.
3. **`sqlite3`** — старый асинхронный драйвер на колбэках, около 1 млн скачиваний в неделю. Нативный аддон.
4. **`sql.js`** — SQLite, скомпилированный в WASM.
5. **CLI `sqlite3` через `child_process`** — запуск бинарника на каждый запрос.

## Сравнение

| Критерий | 1. `node:sqlite` | 2. `better-sqlite3` | 3. `sqlite3` | 4. `sql.js` | 5. CLI |
|---|---|---|---|---|---|
| C7: «стандартные возможности Node» | ✅ буквально | 🟡 трактовка «SQLite из стека включает драйвер» | 🟡 то же | 🟡 то же | ✅, но это хак |
| Зрелость API | 🟡 Release candidate | ✅ стабилен много лет | ✅ | ✅ | — |
| Сборка в Docker | ✅ ничего не собираем | 🟡 node-gyp или prebuild, на alpine нужны python/make/g++ | 🟡 то же | ✅ | 🟡 нужен бинарник в образе |
| API | синхронный, prepared statements | синхронный, prepared statements | асинхронный, колбэки | синхронный | текст через stdout |
| Данные на диске (C2) | ✅ | ✅ | ✅ | ❌ БД живёт **в памяти**, файл — ручной экспорт. Прямо противоречит C2 | ✅ |
| Параметризованные запросы | ✅ `?`, `:name` | ✅ | ✅ | ✅ | ❌ риск SQL-инъекций |
| Версия Node | ≥ 24.15 для RC без предупреждений | ≥ 18 | ≥ 18 | любая | любая |
| Риск на интервью | «почему RC?» — защищается | «это же сторонняя библиотека» — спорно | то же + устаревший стиль | нарушение C2 | несерьёзно |

Варианты 4 и 5 отпадают сразу: один нарушает C2, другой небезопасен. Реальный выбор — между 1 и 2. Это выбор между буквой C7 и зрелостью API.

## Решение (рекомендация)

**Вариант 1: `node:sqlite` на Node.js 24 LTS.**

- **Версия:** `engines.node: ">=24.15.0"`, `.nvmrc` = `24`, Docker-образ `node:24-alpine`. С ТЗ это **не конфликтует**: 24 ≥ 18. Node 18 и 20 к тому же уже EOL.
- **Почему 24, а не 26:** 26 станет LTS только 28.10.2026, а до этого это Current. Для сдачи берём актуальную LTS.
- **Почему не 22:** там модуль experimental и печатает предупреждение при каждом запуске. Это шум в логах и лишний вопрос от проверяющего.

### Как работаем с драйвером

| Аспект | Решение |
|---|---|
| Подключение | Одно соединение `DatabaseSync` на процесс (SQLite — один файл, пул не нужен) |
| PRAGMA при старте | `journal_mode = WAL` (читатели не блокируют писателя), `foreign_keys = ON` (явно, хотя это и дефолт), `busy_timeout` через опцию `timeout`, `synchronous = NORMAL` |
| Запросы | Только prepared statements с параметрами. Склейка SQL из пользовательских строк запрещена (урок «Работа с БД») |
| Транзакции | Хелпер `withTransaction(fn)`: `BEGIN` → `fn` → `COMMIT`, при ошибке `ROLLBACK` и проброс ошибки |
| Граница | Драйвер виден только в `db/` и репозиториях. Сервисы работают с интерфейсами репозиториев |
| Интерфейс репозиториев | **Асинхронный** (`Promise`), хотя драйвер синхронный. Тогда адаптер Postgres в `platform` подключается без изменений сервисов (порт ↔ адаптер) |

### Синхронный драйвер и Event Loop

Курс учит не блокировать основной поток. Почему синхронный драйвер здесь допустим:
- SQLite — встроенная библиотека, запрос к локальному файлу с индексом занимает микросекунды. Сетевого ожидания, ради которого существует async, здесь нет.
- `better-sqlite3` синхронный по той же причине, и это его осознанный дизайн.
- Тяжёлые операции не допускаем: история читается по индексу `(cryptocurrency_id, fetched_at)` с обязательным `limit`, агрегаты — см. Q5.

## Последствия

- ➕ Ноль runtime-зависимостей для БД, C7 выполнен буквально. Нет нативной сборки, Docker-образ проще и меньше.
- ➕ Сильная история для интервью: знание актуальной платформы, осознанный выбор LTS, аргумент про синхронный I/O.
- ➖ API в статусе RC: в теории возможны изменения. Риск ограничен: модуль спрятан за слоем `db/`, замена на `better-sqlite3` затронет один файл.
- ➖ **Локально нужен Node 24**, сейчас стоит 22.23. Нужно поставить через nvm-windows или fnm. Через Docker работает и без этого.
- ➖ Типы `node:sqlite` берём из `@types/node@24`.
- Остаётся на следующие ADR: механизм миграций (модель данных), точность цены (Q4), агрегаты (Q5).

## Как защищать на интервью

«ТЗ разрешает только указанные библиотеки и стандартные возможности Node. Драйвера SQLite в списке нет, а в Node 24 LTS он встроен: `node:sqlite` с версии 24.15 — release candidate. Node 24 удовлетворяет требованию 18+, а 18 и 20 уже EOL. Драйвер синхронный, но для встроенной SQLite это норма: запрос по индексу — микросекунды, сети нет. Интерфейс репозиториев при этом асинхронный, чтобы завтра подключить Postgres без переписывания сервисов».
