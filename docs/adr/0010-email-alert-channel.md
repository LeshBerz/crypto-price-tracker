# 0010. Email-канал алертов в рамках ограничений

- **Статус:** Accepted (06.10.2026)
- **Дата:** 06.10.2026
- **Вопрос брифа:** Q10
- **Требования:** C2, C4/C5 (секреты, таймауты), C7; бриф §3 «Алерты» и правило расширений api (решение от 06.10)
- **Связано:** [0004 — C7](0004-c7-interpretation-and-dev-tooling.md), [0009 — HTTP-стабы](0009-testing-strategy.md)

## Контекст

- Алерты — расширение, а не ТЗ. В `apps/api` они допустимы при трёх условиях из брифа: только разрешённые библиотеки, отдельный модуль, ТЗ-эндпоинты не меняются.
- Каналы идут через порт `Notifier`. Telegram (Bot API) и webhook с HMAC (`node:crypto`) реализуются на axios без вопросов. Email — нет: стандартный путь (`nodemailer` по SMTP) запрещён C7.
- Запуск только локальный (`docker compose up`). Тот, кто запускает проект, **не будет** заводить аккаунт у почтового провайдера и подтверждать домен. Значит, канал должен демонстрироваться без внешних аккаунтов.

### Проверено руками

| Проверка | Результат |
|---|---|
| Mailpit v1.31.4 в Docker: `POST /api/v1/send` (JSON: `From`, `To`, `Subject`, `Text`, `HTML`, `Headers`) | ✅ `{"ID": "…"}`, письмо видно в `GET /api/v1/messages` и в веб-интерфейсе |
| HTTP-API Resend: `POST https://api.resend.com/emails`, `Authorization: Bearer …`, JSON `from/to/subject/html`, поддержка ключа идемпотентности | по документации ([пример Expo](https://docs.expo.dev/guides/using-resend/)) |

## Варианты

1. **Свой SMTP-клиент на `node:net` / `node:tls`.** EHLO, STARTTLS, AUTH, DATA, dot-stuffing, MIME, кодирование заголовков (RFC 2047).
2. **HTTP-API почтового провайдера через axios.** Локально — Mailpit (у него есть HTTP-API отправки), для реальной отправки — провайдер с HTTP-API (эталонный адаптер — Resend).
3. **Email только в `platform`** через `nodemailer` + SMTP. В `apps/api` email нет.
4. **Без email.** Хватит дашборда (SSE), Telegram и webhook.

## Сравнение

| Критерий | 1. Свой SMTP | 2. HTTP-API | 3. Только `platform` | 4. Без email |
|---|---|---|---|---|
| C7 в `apps/api` | ✅ | ✅ axios | ✅ (email вне api) | ✅ |
| Объём и риск кода | ❌ ~300+ строк протокола, TLS-апгрейд, кодировки, MIME — легко ошибиться | ✅ один POST на адаптер | ✅ библиотека | ✅ |
| Демо без внешних аккаунтов | ✅ Mailpit по SMTP | ✅ Mailpit по HTTP | ✅ Mailpit | — |
| Реальная отправка | 🟡 нужен SMTP-relay с AUTH | ✅ ключ в env | ✅ | ❌ |
| Ошибки и ретраи | ❌ коды SMTP, частичные ответы | ✅ HTTP-статусы, идемпотентность | ✅ | — |
| Тестируемость (ADR 0009) | 🟡 нужен SMTP-стаб | ✅ тот же паттерн HTTP-стаба, что для CMC | ✅ | — |
| Индустриальная норма | 🟡 legacy | ✅ транзакционную почту сегодня шлют через HTTP-API провайдеров | ✅ | — |

## Решение (рекомендация)

**Вариант 2: email в `apps/api` через HTTP-API. Адаптер `mailpit` обязательный (локально и в демо), адаптер `resend` — опциональный, по приоритету Could.**

### Адаптеры порта `Notifier` для email

| Адаптер | Когда | Конфиг (env) |
|---|---|---|
| `mailpit` | по умолчанию в `docker compose`. Mailpit — сервис compose с веб-интерфейсом на `:8025`, где видны отправленные письма | `EMAIL_PROVIDER=mailpit`, `MAILPIT_URL` |
| `resend` | реальная отправка, если есть ключ и подтверждённый домен | `EMAIL_PROVIDER=resend`, `RESEND_API_KEY` (только env, в логах маскируется) |
| не задан | email-канал выключен. Правило с email-каналом при создании → 422 «канал не настроен» | — |

Оба адаптера — около 40 строк на axios, с таймаутом и классификацией ошибок:
- 4xx (кроме 429) — **постоянная** ошибка, ретраить бессмысленно;
- 429, 5xx, таймаут — **временная** ошибка, ретраим.

### Доставка: outbox в БД, а не очередь в памяти

Это касается всех каналов, а не только email. Подробнее — в событийной модели.
- **Сработавший алерт пишет запись в `alert_deliveries`** в той же транзакции, что и событие: канал, адресат, payload, `status` (`pending` → `sent` / `failed`), `attempts`, `next_attempt_at`, `last_error`.
- **Фоновая задача забирает `pending`**, у которых `next_attempt_at ≤ now`. Ретраи — с exponential backoff + jitter, максимум N попыток.
- **Почему так.** Очередь ретраев в памяти нарушила бы C2 («данные не в памяти») и терялась бы при перезапуске. Outbox переживает рестарт и виден оператору в мониторинге.
- **Семантика — at-least-once.** Ключ идемпотентности = id доставки: передаём его провайдеру, у Resend есть поддержка. Где провайдер не умеет идемпотентность (Telegram), дубль при сбое между отправкой и фиксацией статуса возможен. Это задокументированный компромисс.
- **В `platform`** тот же outbox публикуется в RabbitMQ с DLQ (как в Korefan, Q8).

### Безопасность

- **Экранирование.** Данные в HTML-письме (символ, название из CMC, пороги) экранируются, иначе возможна HTML-инъекция в письме.
- **Адресаты.** Задаёт только Operator (scope `ops:write`, ADR 0002). Формат email валидируется, число адресатов ограничено. Опционально — allowlist доменов в env (`EMAIL_ALLOWED_DOMAINS`), чтобы сервис нельзя было превратить в спам-рассыльщик.
- **Защита от шквала.** Cooldown правила (не чаще раза в N минут) — в ADR алертов.

### Тесты (по ADR 0009)

- Оба адаптера — против HTTP-стаба на `node:http`: успех, 400, 401, 429, 500, таймаут, проверка заголовков и экранирования.
- Outbox: ретраи с `FakeClock`, переход в `failed` после N попыток, повторный запуск не шлёт уже отправленное.
- E2e (Playwright): сработал алерт → письмо появилось в Mailpit (`GET /api/v1/messages`).

## Последствия

- ➕ Email работает «из коробки» в `docker compose up` без аккаунтов: достаточно открыть `localhost:8025`, чтобы увидеть письмо.
- ➕ Ноль новых runtime-зависимостей, C7 соблюдён. SMTP не реализуем руками — меньше рискованного кода.
- ➕ Outbox даёт надёжную доставку для всех каналов, соблюдает C2 и даёт хорошую тему для интервью (transactional outbox, at-least-once, идемпотентность).
- ➖ Mailpit — ещё один сервис в compose (лёгкий, ~15 МБ RAM по замеру).
- ➖ Адаптер `resend` проверяется только против стаба. Реальную отправку проверяем вручную, если появится ключ.
- ➖ Приоритет: email — последний из каналов. Порядок: дашборд (SSE) → webhook → Telegram → email. Если время поджимает, email режется первым (MoSCoW: Could).

## Как защищать на интервью

«Nodemailer нельзя по ТЗ, а писать SMTP руками — риск без пользы. Транзакционную почту сегодня шлют через HTTP-API провайдеров, это обычный axios-запрос. Локально стоит Mailpit, у него тоже есть HTTP-API, так что письма видны без аккаунтов. Доставки лежат в outbox-таблице, а не в памяти: так требует ТЗ, и ретраи переживают рестарт. Семантика at-least-once, с ключом идемпотентности там, где провайдер его поддерживает».
