# 0018. Web: гид-тренер (onboarding tour) и анимации

- **Статус:** Proposed (08.10.2026)
- **Дата:** 08.10.2026
- **Фаза:** C (дизайн `apps/web`, итерация 2) — [README дизайна](../project/design/README.md#перенос-в-appsweb)
- **Связано:** [0012 — shadcn/ui на Base UI, Tailwind 4](0012-web-charts-and-ui-kit.md), [0001 — Next.js 16](0001-web-framework.md). Ограничение C7 на `apps/web` не действует, но выбор зависимостей — за заказчиком

## Контекст

Во второй итерации макетов появились:
- **гид-тренер** — пошаговый тур с «прожектором» на элемент, туры по экранам и ролям, режим презентации по всем экранам подряд;
- **анимации** — перетекающий индикатор навигации, раскрытие «линзы точности», переходы прожектора.

В макетах всё это написано на чистом JS: [`mockups/*.html`](../project/design/mockups/), ядро гида — около 200 строк. Проверено в headless Chrome:
- все 5 туров проходятся с клавиатуры до конца;
- ловушка фокуса работает;
- при `prefers-reduced-motion` переходов нет;
- режим презентации доигрывает 4 экрана.

Вопрос: как это перенести в Next.js 16 + shadcn/ui. Варианты — взять библиотеку тура или перенести своё; для анимаций — библиотека или CSS.

### Требования к гиду (из брифа итерации 2)

| # | Требование | Почему важно |
|---|---|---|
| T1 | Туры по экранам и ролям (Viewer видит меньше шагов) | шаги фильтруются по роли сессии |
| T2 | Ловушка фокуса, ←/→/Esc, `aria-live`, `role="dialog"` | WCAG 2.2 AA (2.1.1, 2.4.3, 4.1.3) |
| T3 | Плавные переходы; без анимаций при `prefers-reduced-motion` | WCAG 2.3.3, принцип «спокойный realtime» |
| T4 | Режим презентации: автопроигрывание через несколько страниц | демо продукта заказчиком |
| T5 | Карточка в стиле продукта: токены shadcn, иконки Lucide, «Данные: операция API» | своё лицо продукта (фидбек заказчика) |
| T6 | Отметка «пройдено» на пользователя | в макете — `localStorage`; в проде — см. «Последствия» |

## Решение (рекомендация)

1. **Гид — свой компонент `<GuidedTour>`** (вариант 5):
   - карточка — Base UI `Dialog` (модальность и ловушка фокуса от примитива shadcn);
   - прожектор — свой элемент с `box-shadow` (как в макете);
   - позиционирование — утилиты Floating UI, которые уже лежат внутри Base UI;
   - шаги — данные (`{ el, title, body, api, roles }`) рядом с экраном;
   - режим презентации — параметр `?present=1` и `router.push` на следующий экран.
   
   **Запасной вариант — react-joyride 3**, если на реализацию не хватит времени фазы C. Совместимость с React 19, MIT и заявленная доступность делают его лучшим из готовых.
2. **Анимации — CSS transitions на токенах** (длительности и кривые — в `@theme` Tailwind). View Transitions — только как прогрессивное улучшение для смены вкладок оператора, после проверки поддержки. **motion не берём**, пока не появятся жесты или layout-анимации.
3. **Иконки — `lucide-react`** (ISC). Это набор shadcn/ui по умолчанию, и именно его иконки стоят в макетах.

## Последствия

- ➕ Доступность гида — наша и проверяемая. В e2e Playwright (ADR 0009) можно пройти тур клавиатурой — тот же сценарий, что в проверке макетов.
- ➕ Ноль новых runtime-зависимостей, кроме `lucide-react`. Стиль гида совпадает с продуктом.
- ➕ Темы для интервью: ловушка фокуса, `aria-live` против live-регионов на каждый тик, `prefers-reduced-motion`, почему не AGPL.
- ➖ ≈ 200–300 строк своего кода и тесты. Края, которые библиотеки уже прошли: скролл внутри контейнеров, элементы в порталах, изменение размеров.
- ➖ **Где хранить «пройдено».** В макете это `localStorage`. В проде, чтобы отметка была на пользователя, а не на браузер, — колонка `onboarding_completed_at` в `web.db` (ADR 0016). Это изменение схемы web, его решаем отдельно — открытый вопрос в README дизайна.
- Если выбран запасной вариант (react-joyride), карточку делаем своим tooltip-компонентом на токенах shadcn, а ловушку фокуса проверяем e2e.

## Как защищать на интервью

«Гид я сначала сделал в макете на чистом JS и проверил headless-браузером: все туры проходятся с клавиатуры, фокус не уходит из карточки, при reduced motion анимаций нет. Из библиотек самая популярная — driver.js, но у неё в документации нет ни ловушки фокуса, ни ARIA. Shepherd под AGPL. React-joyride — разумный запасной вариант. А своя реализация — 200 строк на примитивах, которые уже есть в shadcn, и каждую я могу объяснить. Анимации — на CSS: их четыре, и тащить motion ради них не нужно».
