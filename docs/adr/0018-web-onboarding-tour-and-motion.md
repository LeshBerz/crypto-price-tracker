# 0018. Web: гид-тренер (onboarding tour) и анимации

- **Статус:** Accepted (11.10.2026) — свой компонент гида, CSS-анимации, `lucide-react`. Поправки C9 от 12.10.2026 — [ниже](#поправки-c9-12102026)
- **Дата:** 08.10.2026
- **Фаза:** C (дизайн `apps/web`, итерация 2) — [README дизайна](../project/design/README.md#перенос-в-appsweb)
- **Связано:** [0012 — shadcn/ui на Base UI, Tailwind 4](0012-web-charts-and-ui-kit.md), [0001 — Next.js 16](0001-web-framework.md). Ограничение C7 на `apps/web` не действует, но каждая зависимость утверждается отдельным решением

## Контекст

Во второй итерации макетов появились:
- **гид-тренер** — пошаговый тур с «прожектором» на элемент, туры по экранам и ролям, режим презентации по всем экранам подряд;
- **анимации** — перетекающий индикатор навигации, раскрытие «линзы точности», переходы прожектора.

В макетах всё это написано на чистом JS: [`mockups/*.html`](../project/design/mockups/), ядро гида — около 200 строк. Проверено в headless Chrome:
- все 5 туров проходятся с клавиатуры до конца;
- ловушка фокуса работает;
- при `prefers-reduced-motion` переходов нет;
- режим презентации доигрывает 4 экрана.

Вопрос: как это перенести в Next.js 16 + shadcn/ui. Варианты — взять библиотеку тура или перенести своё; для анимаций — библиотека или CSS.

### Требования к гиду (из брифа итерации 2)

| # | Требование | Почему важно |
|---|---|---|
| T1 | Туры по экранам и ролям (Viewer видит меньше шагов) | шаги фильтруются по роли сессии |
| T2 | Ловушка фокуса, ←/→/Esc, `aria-live`, `role="dialog"` | WCAG 2.2 AA (2.1.1, 2.4.3, 4.1.3) |
| T3 | Плавные переходы; без анимаций при `prefers-reduced-motion` | WCAG 2.3.3, принцип «спокойный realtime» |
| T4 | Режим презентации: автопроигрывание через несколько страниц | демо продукта |
| T5 | Карточка в стиле продукта: токены shadcn, иконки Lucide, «Данные: операция API» | своё лицо продукта (итерация 2 макетов) |
| T6 | Отметка «пройдено» на пользователя | в макете — `localStorage`; в проде — см. «Последствия» |

## Решение

1. **Гид — свой компонент `<GuidedTour>`** (вариант 5):
   - карточка — Base UI `Dialog` (модальность и ловушка фокуса от примитива shadcn);
   - прожектор — свой элемент с `box-shadow` (как в макете);
   - позиционирование — утилиты Floating UI, которые уже лежат внутри Base UI;
   - шаги — данные (`{ el, title, body, api, roles }`) рядом с экраном;
   - режим презентации — параметр `?present=1` и `router.push` на следующий экран.
   
   **Запасной вариант — react-joyride 3**, если на реализацию не хватит времени фазы C. Совместимость с React 19, MIT и заявленная доступность делают его лучшим из готовых.
2. **Анимации — CSS transitions на токенах** (длительности и кривые — в `@theme` Tailwind). View Transitions — только как прогрессивное улучшение для смены вкладок оператора, после проверки поддержки. **motion не берём**, пока не появятся жесты или layout-анимации.
3. **Иконки — `lucide-react`** (ISC). Это набор shadcn/ui по умолчанию, и именно его иконки стоят в макетах.

## Последствия

- ➕ Доступность гида — своя и проверяемая. В e2e Playwright (ADR 0009) можно пройти тур клавиатурой — тот же сценарий, что в проверке макетов.
- ➕ Ноль новых runtime-зависимостей, кроме `lucide-react`. Стиль гида совпадает с продуктом.
- ➕ Темы для интервью: ловушка фокуса, `aria-live` против live-регионов на каждый тик, `prefers-reduced-motion`, почему не AGPL.
- ➖ ≈ 200–300 строк своего кода и тесты. Края, которые библиотеки уже прошли: скролл внутри контейнеров, элементы в порталах, изменение размеров.
- ➖ **Где хранить «пройдено».** В макете это `localStorage`. В проде, чтобы отметка была на пользователя, а не на браузер, — колонка `onboarding_completed_at` в `web.db` (ADR 0016). Решение Q14 от 11.10: колонка входит в первую миграцию `web.db` (задача C1), поправка к ADR 0016.
- Если выбран запасной вариант (react-joyride), карточка делается своим tooltip-компонентом на токенах shadcn, а ловушка фокуса проверяется e2e.

## Реализация движения (C11, 12.10.2026)

- Длительности и кривая — токены в [`globals.css`](../../apps/web/src/app/globals.css): `--duration-fast` 120 мс (наведение, нажатие), `--duration-base` 200 мс (раскрытие блока, строка списка, диалог, маркер навигации), `--duration-slow` 320 мс (уведомление), `--ease-out`. Компоненты ссылаются на токены, а не на числа.
- Анимации: появление строки списка, раскрытие блока по высоте, маркер навигации, всплывающие блоки, уведомление, вспышка изменившейся цены. Все — CSS; `motion` по-прежнему не используется.
- `prefers-reduced-motion: reduce` обнуляет длительности одним правилом для всех элементов.
- Не сделано: анимация исчезновения строки. Для неё элемент нужно держать в DOM после удаления из данных — отдельный механизм, который ради одного эффекта не вводится.
- Новых зависимостей нет: раскрывающийся блок, подсказки, пояснения и список — примитивы уже установленного Base UI.

## Поправки (C9, 12.10.2026)

Утверждены 12.10.2026 при разборе задачи C9. Основное решение не меняется: гид — свой компонент, запасной вариант (react-joyride) не понадобился.

| # | Решение | Почему |
|---|---|---|
| 1 | **T6: отметка на каждый экран, а не одна на пользователя.** Таблица `user_tours` в `web.db` вместо колонки `onboarding_completed_at` ([ADR 0016, поправка 37](0016-web-auth-and-bff-routes.md#поправки-c9-1210)). Пропущенный тур отмечается так же, как пройденный | В макете гид открывается сам при первом открытии каждого экрана; одна отметка оставила бы автозапуск только дашборду |
| 2 | **Четыре тура, как в макете:** вход (3 шага), дашборд (Viewer 8, Operator 9), карточка монеты (7), панель оператора (12 — к одиннадцати шагам макета добавлен раздел «Пользователи», которого в макете не было). Отметка тура входа — `localStorage` | До входа пользователя нет, хранить отметку в `web.db` не для кого |
| 3 | **T4, режим презентации, отложен.** В C9 не входит; компонент принимает шаги и адреса разделов данными, поэтому автопроигрывание добавляется без переделки | В оценку C9 режим не входил; очерёдность — e2e, скриншоты и тексты к отправке |
| 4 | **Клавиши <kbd>G</kbd> нет** (решение Q16). Гид открывают кнопка «Гид» в шапке и ссылка «Пройти гид заново» в футере. Стрелки действуют только при открытом диалоге и под это требование не попадают |
| 5 | **Положение карточки — свои чистые функции** ([`lib/tour/layout.ts`](../../apps/web/src/lib/tour/layout.ts)), а не утилиты Floating UI | Floating UI — зависимость Base UI, а не проекта: прямой импорт привязал бы код к внутренностям чужого пакета. Правил немного (под целью → над → у свободного края → сбоку), и они проверяются тестами без DOM |
| 6 | **Нажатия во время перехода не копятся, а игнорируются.** В макете они проигрывались по очереди | Пока открывается раздел оператора, несколько быстрых «Далее» перескакивали шаги, которых пользователь не видел, и добавляли лишние записи в историю браузера. Найдено проверкой в браузере |

### Реализация

- **Карточка** — Base UI `Dialog` в режиме `trap-focus`: ловушка фокуса, <kbd>Esc</kbd>, возврат фокуса — от примитива. Полный модальный режим не взят: он блокирует прокрутку страницы, а гид сам подводит цель к верху окна. Нажатия мимо карточки принимает прозрачная подложка; `aria-modal` выставлен явно.
- **Прожектор** — один элемент с `box-shadow` (рамка и затемнение на весь экран), положение и размер — переходами на токенах движения.
- **Цель шага** — атрибут `data-tour` у элемента экрана. У списка две раскладки (таблица и карточки), берётся первая видимая. Цели нет (на паузе нет ни одной монеты) — шаг показывается по центру без прожектора.
- **Гид оператора** идёт по четырём адресам: шаг знает свой раздел и открывает его перед показом.
- **Автозапуск** — через 800 мс после открытия экрана, если тура нет среди пройденных. Список пройденных приходит со страницей (серверный layout).
- **Телефон** (уже 640 px): карточка во всю ширину у края окна, дальнего от цели.

Проверено в браузере на локальном стенде: четыре тура пройдены с клавиатуры до конца, под Operator и Viewer, на широком экране и на 375 px, в обеих темах; отметка сохраняется и переживает перезагрузку, «Пройти гид заново» её снимает. Не проверено: плотность затемнения глазами (панель браузера, в которой шла проверка, не отрисовывает на снимке полупрозрачный слой во весь экран), скринридеры, Firefox и Safari, собранный образ.

## Как защищать на интервью

«Гид я сначала сделал в макете на чистом JS и проверил headless-браузером: все туры проходятся с клавиатуры, фокус не уходит из карточки, при reduced motion анимаций нет. Из библиотек самая популярная — driver.js, но у неё в документации нет ни ловушки фокуса, ни ARIA. Shepherd под AGPL. React-joyride — разумный запасной вариант. А своя реализация — 200 строк на примитивах, которые уже есть в shadcn, и каждую я могу объяснить. Анимации — на CSS: их четыре, и тащить motion ради них не нужно».
