# 20. Запуск и окружение

> **Опорный принцип** (тема «Структура и архитектура Node.js-приложений», по карте тем `course-map.md`): «SoC — каждый слой отвечает за своё: запросы, бизнес-логика, данные, конфиг, утилиты».

## Простыми словами

Код один, а запусков много: в Docker и без него, на стабе и с настоящим CoinMarketCap, с веб-клиентом и без. Отличаются они только окружением — набором переменных. Поэтому конфигурация вынесена из кода в один файл `.env`, а приложение при старте читает его, проверяет и либо работает, либо сразу объясняет, чего не хватает.

Аналогия: приложение — прибор, `.env` — его настройки на отдельной табличке. Прибор один и тот же; табличку меняют под место установки. Если на табличке ошибка, прибор не включается и называет строку с ошибкой — это лучше, чем включиться и работать неверно.

## Как это в Nest → как в Express

| Задача | Nest | Здесь |
|---|---|---|
| Прочитать `.env` | `@nestjs/config` (внутри `dotenv`) | Флаг Node.js `--env-file-if-exists` в строке запуска — зависимости нет |
| Проверить значения | `ConfigModule.forRoot({ validationSchema })` | Функция `loadConfig(env)` — возвращает типизированный объект или бросает `ConfigError` со всеми проблемами сразу |
| Получить значение в коде | `ConfigService.get()` | Объект `Config` передаётся параметром; `process.env` читается в одном месте |
| Запустить TypeScript | `ts-node`, `nest start --watch` | `node --watch src/server.ts` — Node 24 сам убирает типы |
| Драйвер БД | пакет (`pg`, `better-sqlite3`) | встроенный `node:sqlite` |

Общий вывод: то, что в Nest делают пакеты, здесь делает сам рантайм. Поэтому версия Node.js — жёсткое требование, а не пожелание.

## В проекте

### Версия Node.js

- [`.nvmrc`](../../.nvmrc) и `engines` в [`package.json`](../../package.json) — версия записана в двух местах: первое читают менеджеры версий и CI, второе — npm.
- [`.npmrc`](../../.npmrc) — `engine-strict=true`. Без него npm на неподходящей версии печатает предупреждение `EBADENGINE` и продолжает; с ним — останавливается.
- Обоснование версии — [ADR 0003](../adr/0003-sqlite-driver-and-node-version.md).

### Зависимости

- `npm ci` — установка строго по `package-lock.json`: сначала удаляет `node_modules`, затем ставит записанные версии. Файл блокировки не меняет. `npm install` может обновить версии в пределах диапазонов и переписать файл блокировки. Для воспроизводимого запуска и CI — `npm ci`.
- Workspaces: в корневом `package.json` перечислены `apps/api` и `apps/web`. Одна установка в корне ставит зависимости обоих пакетов в общий `node_modules`. Флаг `-w @cpt/api` запускает скрипт пакета и переходит в его каталог.

### Один файл окружения

- [`.env.example`](../../.env.example) — шаблон со всеми переменными.
- api: строки запуска в [`apps/api/package.json`](../../apps/api/package.json) — `--env-file-if-exists=../../.env`.
- web: [`root-env.ts`](../../apps/web/src/server/root-env.ts) — разбирает корневой файл через `util.parseEnv` и не кладёт его в `process.env`: ключ CoinMarketCap в процесс web не попадает.
- compose: [`docker-compose.yml`](../../docker-compose.yml) — подставляет `${ИМЯ:-значение по умолчанию}`; сам файл в контейнер не копируется.
- Проверка: [`apps/api/src/config.ts`](../../apps/api/src/config.ts), [`apps/web/src/server/config.ts`](../../apps/web/src/server/config.ts).
- Решение — [ADR 0004, поправка от 12.10](../adr/0004-c7-interpretation-and-dev-tooling.md). Справочник — [Окружение](../guides/environment.md).

### Приоритет значений

Переменная процесса → файл пакета (`apps/api/.env`) → корневой `.env` → значение по умолчанию в коде. Поэтому стаб можно включить на один запуск, не трогая файл: `CMC_BASE_URL=http://localhost:4010 npm run dev -w @cpt/api`.

### Стаб и настоящий CoinMarketCap

Источник выбирает одна переменная — `CMC_BASE_URL`. Значение по умолчанию разное: в compose — стаб (запуск без ключа и интернета), локально — настоящий CoinMarketCap (значение по умолчанию в коде). Таблица — в [обзоре гайдов](../guides/README.md#стаб-и-настоящий-coinmarketcap).

### Гайды

Запуск описан не одним разделом README, а отдельными страницами по сценариям: [`docs/guides/`](../guides/README.md). У каждого сценария — свои шаги и своя проверка, включая отрицательную: `SOL` на стабе даёт 422, на настоящем CoinMarketCap — 201.

## Подводные камни

Все четыре найдены при прохождении README на машине с Windows.

- **`EPERM … unlink … .node` при `npm ci`.** Windows не даёт удалить открытый файл. Нативный модуль `next-swc` держал работающий dev-сервер web; `npm ci` успел удалить часть `node_modules` и остановился. Следствие — `Cannot find package 'express'`. Перед установкой процессы проекта останавливаются.
- **`.env not found. Continuing without it.`** Сообщение относится к необязательному `apps/api/.env`, а не к корневому файлу. В режиме `--watch` печатается дважды: Node.js запускает наблюдающий процесс и дочерний, оба читают аргументы.
- **`$` в `.env` и Docker Compose.** Compose подставляет переменные в значениях файла. Хэш `scrypt$17$8$1$…` без одинарных кавычек превращается в обрезанную строку, а compose предупреждает `The "…" variable is not set`. Node.js (`--env-file`, `util.parseEnv`) подстановку не делает — поэтому локально тот же файл работает, а в Docker нет.
- **`restart: unless-stopped` и ошибка конфигурации.** Контейнер, который завершился на старте, перезапускается по кругу. Сообщение об ошибке должно называть причину и способ исправления — оно повторится в логах десятки раз, и это единственное, что видит человек.
- **`cp .env.example .env`** перезаписывает существующий файл без вопроса — вместе с ключами.
- **Разные базы.** Docker хранит базы в томах, локальный запуск — в `apps/*/data`. API-ключ, выпущенный в одном, не действует в другом.

## Вопросы на собеседовании

1. Чем `npm ci` отличается от `npm install`? → `ci` ставит ровно по файлу блокировки, удаляя `node_modules`, и падает, если файл блокировки расходится с `package.json`; `install` может обновить версии и переписать файл блокировки.
2. Почему в проекте нет `dotenv`? → Node.js читает файл сам (`--env-file-if-exists`); ограничение ТЗ на зависимости соблюдается без компромисса в удобстве.
3. Что произойдёт, если не задать `CMC_API_KEY`? → Сервис не стартует: `loadConfig` собирает все проблемы и бросает `ConfigError` с именами переменных, значения в сообщение не попадают.
4. Почему один и тот же `.env` работает локально и ломается в Docker? → Compose подставляет `$…` в значениях, Node.js — нет; значения со знаком `$` берутся в одинарные кавычки.
5. Почему значение `CMC_BASE_URL` по умолчанию в compose и в коде разное? → В compose важен запуск без ключа и интернета — стаб; в коде значение по умолчанию — настоящий адрес, чтобы продакшен не зависел от забытой переменной.
