# 16. Web: дашборд, кэш запросов и realtime

> **Из курса** (урок «Авторизация, API и внешние источники», по конспекту `course-map.md`): «…учитывать rate limit, кэшировать, graceful degradation».

На дашборде это три вещи: кэш ответов api в браузере, обновление кэша событиями вместо опроса и экран, который при сбое показывает последние данные и честно говорит, что с ними не так.

## Простыми словами
Дашборд — табло в аэропорту. Расписание загружают один раз (три запроса). Дальше диспетчер по громкой связи сообщает только изменения («рейс 12 — новое время»), и табло правит одну строку, а не перечитывает всё расписание. Если связь с диспетчером пропала, табло не гаснет: на нём остаётся последнее известное расписание и появляется надпись «данные на 14:05».

- **Кэш запросов (TanStack Query)** — табло: хранит ответы по ключам `['prices']`, `['sparklines', окно]`, `['cryptocurrencies']`.
- **Поток событий (SSE)** — громкая связь: `price.updated` правит строку кэша без запроса; `sync.finished` и `watchlist.changed` просят перечитать данные.
- **Баннер деградации** — надпись о состоянии данных. Одна, самая серьёзная из причин.

## Как это в Nest → как в Next.js и React
| Задача | Nest (сервер) | Здесь (браузер) |
|---|---|---|
| Типизированный клиент к API | `HttpService` + DTO | [`bff-client.ts`](../../apps/web/src/lib/bff-client.ts): путь, параметры и тип ответа выводятся из сгенерированного `paths` |
| Кэш ответов | `CacheModule`, ключ кэша | TanStack Query: ключ запроса, `staleTime`, `setQueryData` |
| Подписка на события | `@Sse()` отдаёт поток, `EventEmitter2` слушает | `EventSource` читает поток, обработчик пишет в кэш |
| Единый формат ошибок | `ExceptionFilter` → Problem | `BffError`: статус, Problem, источник отказа (`api` / `web` / `network`) |
| Логика отдельно от транспорта | сервис без `req`/`res` | чистые функции без React и сети: разбор события, правка списка, выбор баннера |

Последняя строка — главный приём этапа. Всё, что можно проверить без браузера, вынесено в функции и покрыто тестами в Node; компонентам остаётся разметка.

## В проекте

### Клиент BFF на типах контракта
[`bff-client.ts`](../../apps/web/src/lib/bff-client.ts). Тип `GetPath` отбирает из `paths` только пути, у которых есть GET с JSON-ответом. `client.get('/api/v1/prices/sparklines', { query: { window: '7d' } })` проверяется компилятором: опечатка в пути, лишний параметр или `window: '30d'` — ошибка сборки. Путь с `{id}` требует `params`.

Ошибка — `BffError`:
- `status = 0` — ответа нет (сеть);
- `source` — кто отказал: по префиксу типа Problem (`urn:cpt:web:problem:*` — BFF, остальное — api);
- `isUnavailable` — сеть, 502 / 504 или 5xx: данные недоступны не по вине запроса;
- 401 → вызывается `onUnauthorized` (переход на `/login?reason=expired`).

`fetch` и `onUnauthorized` передаются снаружи — в тестах клиент работает с подставным `fetch` без моков модулей.

### Три запроса и ни одного таймера
[`queries.ts`](../../apps/web/src/lib/dashboard/queries.ts), [ADR 0017](../adr/0017-web-ui-data-gaps.md). Дашборд делает три запроса независимо от числа монет. Опроса по таймеру (`refetchInterval`) нет: данные обновляет поток.

### Событие → кэш
[`stream-events.ts`](../../apps/web/src/lib/dashboard/stream-events.ts):

| Событие | Действие |
|---|---|
| `price.updated` | `applyPriceUpdate` возвращает **новый** список с новой ценой; `setQueryData(['prices'])`. Запроса нет. Порядок строк не меняется |
| `sync.finished` | перечитать цены и мини-графики: `change24hPercent` и `isStale` считает сервер, клиент формулы не дублирует (решение Q5 дизайна) |
| `watchlist.changed` | перечитать цены, мини-графики и список монет |
| монета из события не найдена в списке | перечитать список — страховка от потерянного `watchlist.changed` |
| битый JSON, нет нужных полей, незнакомое событие | пропустить |

Детали `applyPriceUpdate`: событие старше цены в списке её не затирает (после переподключения порядок не гарантирован); `isStale` сбрасывается сразу — только что сохранённая цена устаревшей быть не может.

### Фоновый перезапрос не продлевает сессию
Проблема: запрос через `/api/bff` продлевает срок бездействия сессии (2 часа). `sync.finished` приходит каждые 5 минут и вызывает перезапрос — открытая вкладка не вышла бы по бездействию никогда.

Решение ([ADR 0016](../adr/0016-web-auth-and-bff-routes.md), поправка 26): перезапросы по событиям потока идут с заголовком `X-Cpt-Background: 1`, и BFF проверяет сессию без продления (`validate(token, { touch: false })`, [`bff-http.ts`](../../apps/web/src/server/bff/bff-http.ts)). Признак действует только на GET.

Почему заголовку от клиента можно верить: соврав, клиент может только укоротить собственную сессию. Продлить её без действия пользователя признаком нельзя.

На стороне кэша ([`refreshInBackground`](../../apps/web/src/lib/dashboard/queries.ts)) используется `fetchQuery` со своим `queryFn`, а не `invalidateQueries`: тот запустил бы обычный `queryFn` запроса — без признака фона.

### Соединение с потоком
[`stream-connection.ts`](../../apps/web/src/lib/dashboard/stream-connection.ts). У `EventSource` два разных отказа:

| Что случилось | `readyState` | Кто переподключается |
|---|---|---|
| Обрыв сети, сервер закрыл поток | `CONNECTING` | браузер сам |
| Сервер ответил не потоком (401, 502) | `CLOSED` | никто — браузер сдаётся |

Второй случай обрабатывает код: новая попытка через 1, 2, 4 … 30 с и обычный запрос цен, который показывает причину — 401 уводит на вход, 502 включает баннер. После любого повторного открытия состояние перечитывается: пропущенные события api не досылает ([ADR 0014](../adr/0014-api-contract.md)). Событие `session.expired` закрывает поток без новых попыток.

`EventSource` в функцию передаётся фабрикой — в тестах его заменяет объект с методами `open()`, `drop()`, `reject()`, время управляется `jest.useFakeTimers()`.

### Баннер деградации
[`degradation.ts`](../../apps/web/src/lib/dashboard/degradation.ts) — чистая функция «состояние → одна причина», по убыванию серьёзности:

1. `api-unavailable` — перезапрос не удался, на экране данные прошлого ответа (время и `requestId` — в баннере);
2. `partial` — запуск частичный и есть устаревшие цены;
3. `stale` — цены старше двух интервалов; текст зависит от того, все ли монеты устарели и упал ли последний запуск;
4. `sync-failed` — запуск не удался, но цены ещё свежие (мягкое сообщение);
5. `stream-offline` — поток переподключается.

Монета на паузе в подсчёт не идёт ([ADR 0017](../adr/0017-web-ui-data-gaps.md)): пауза — штатное действие оператора. Пока список монет не загружен, устаревшие цены сбоем не объявляются — отличить паузу от сбоя ещё нельзя.

Если данных нет совсем и запрос упал — это не баннер, а карточка ошибки с `requestId` и кнопкой «Повторить».

### Цены — строки до самого экрана
[`format.ts`](../../apps/web/src/lib/format.ts). `Intl.NumberFormat.format()` принимает десятичную строку и форматирует её точно — `Number()` не нужен:

- от 1 — два знака: `$67,123.45`; меньше 1 — шесть значащих цифр: `$0.0000123457`;
- ведущие нули мелкой цены приглушены, но остаются в тексте (решение Q3 дизайна);
- полное значение из api — в подсказке;
- направление подсветки — `compareDecimal`: сравнение двух строк без перевода в число.

Единственное место с `Number()` — координаты мини-графика ([`sparkline.ts`](../../apps/web/src/lib/sparkline.ts)): это пиксели, а не деньги.

### Экран
[`dashboard.tsx`](../../apps/web/src/components/dashboard/dashboard.tsx) собирает запросы, поток и баннер; [`price-table.tsx`](../../apps/web/src/components/dashboard/price-table.tsx) рисует таблицу на широком экране и карточки на узком (решение Q7); [`cells.tsx`](../../apps/web/src/components/dashboard/cells.tsx) — ячейки. `aria-live` стоит только у баннера: тики цен скринридеру не зачитываются.

## Подводные камни
- **`invalidateQueries` по событию потока отменяет срок бездействия.** Найдено на разборе этапа: вариант «просто без таймера» не работал. Фоновые перезапросы помечаются заголовком.
- **Повтор запроса в TanStack Query ждёт видимости вкладки.** У скрытой вкладки запрос с `retry` зависает в состоянии «пауза», ошибка в состояние не попадает — баннер «нет связи с API» не появлялся. У фоновых перезапросов `retry: false`: повтор и так обеспечивает переподключение потока. Найдено при проверке в Docker.
- **`EventSource` не переподключается после ответа с ошибкой HTTP.** Только после обрыва. Остановка api даёт 502 на `/api/stream` — без своего таймера поток не вернулся бы.
- **`fetchQuery` с другим `queryFn` меняет опции запроса в кэше.** Наблюдатель (`useQuery`) при следующем своём запросе ставит свои опции обратно; это закреплено тестом — обычный запрос, фоновый, снова обычный.
- **`$0.5` вместо `$0.50`.** `maximumSignificantDigits` отбрасывает хвостовые нули, а `minimumFractionDigits` вместе с ним не действует. Дробная часть дополняется до двух знаков вручную.
- **Стаб CoinMarketCap отдаёт котировку с неизменным временем.** Повторная синхронизация новой строки цены не создаёт (запись идемпотентна), и через два интервала цена становится `isStale` при успешном запуске. На экране это баннер «цены устарели» без обвинения источника — поведение верное, но при демонстрации на стабе его стоит ожидать.
- **Кэш запросов создаётся в `useState`, а не в модуле.** Модуль на сервере общий для всех запросов — кэш одного пользователя достался бы другому.

## Вопросы на собеседовании
1. **Почему дашборд не опрашивает api по таймеру?** → Сервер уже шлёт события. Опрос — лишняя нагрузка и задержка до интервала; к тому же он продлевал бы сессию без действий пользователя.
2. **Почему `price.updated` пишется прямо в кэш, а `sync.finished` вызывает перезапрос?** → В событии цены есть всё для строки. Изменение за 24 часа и признак «устарела» считает сервер — дублировать формулы на клиенте значит получить два источника правды.
3. **Как открытая вкладка выходит по бездействию, если данные обновляются?** → Фоновые перезапросы помечены заголовком, BFF проверяет сессию без продления. Поток SSE тоже не продлевает.
4. **Что видит пользователь, когда api упал?** → Последние данные, баннер «нет связи с API» со временем данных и `requestId`, индикатор «переподключение». После восстановления экран перечитывает данные сам.
5. **Где в интерфейсе цена превращается в число?** → Нигде, кроме координат мини-графика. Форматирует `Intl.NumberFormat` из строки, сравнивает `compareDecimal`.
