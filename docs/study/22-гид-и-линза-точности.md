# 22. Гид по интерфейсу и «линза точности»

> **Из курса** ([конспект](../course/course-map.md), ценности): «Простота — о сложном кратко и просто, без бюрократии»; деливери — «Что изменилось благодаря моей работе? — факт, цифра, решение».

## Простыми словами

Две детали, которые делают видимым то, что обычно остаётся в коде.

**Линза точности.** Сервис хранит цену строкой и нигде не переводит её в число — это главное инженерное решение проекта (ADR 0006). Но на экране цена округлена до `$67,123.45`, и решения не видно. Линза — кнопка на месте цены: нажатие раскрывает строку из api целиком, а цифры, срезанные округлением, подсвечены. Аналогия: чек в магазине показывает «итого 100 ₽», а линза — тот же чек с копейками и строкой «округлено».

**Гид.** Пошаговый тур: экран затемняется, один элемент остаётся в «прожекторе», рядом карточка с пояснением и строкой «Данные: какая операция api за этим стоит». Это одновременно подсказка новому пользователю и сценарий демонстрации: каждый шаг называет решение и его источник.

Оба компонента — свои, без новых зависимостей: всплывающий блок и диалог уже есть в Base UI.

## Как это в Nest → как в Express → как в React

| Идея | Nest | Express | Здесь |
|---|---|---|---|
| Данные отдельно от механизма | декораторы-метаданные, по которым работает общий guard | таблица маршрутов, по которой собирается роутер | шаги гида — массив объектов в [`steps.ts`](../../apps/web/src/lib/tour/steps.ts), компонент один |
| Фильтр по роли | `@Roles()` + `RolesGuard` | `requireScope` | `stepsFor(tour, role)`: шаг с полем `roles` виден только этим ролям |
| Чистая логика вне фреймворка | сервис без `@nestjs/*` в импортах | модуль без `express` | `lensView`, `placeCard`, `tourForPath` — функции без React и DOM, тесты в Node |
| Идемпотентная запись | `PUT` с идентификатором в пути | то же | `PUT /api/me/tours/{tour}` — повтор ничего не меняет |

Тот же приём, что у роутера api из спеки (B6): что показывать — данные, как показывать — один компонент. Новый шаг — новая запись в массиве, а не новый код.

## В проекте

### Линза: разбор строки по символам

[`lensView`](../../apps/web/src/lib/price-lens.ts) раскладывает строку цены на цифры с пометками. Числа в коде нет вообще — только длины и позиции символов:

| Цена из api | В интерфейсе | Значащих цифр | Показано | Скрыто округлением |
|---|---|---|---|---|
| `67123.451234567891` | `$67,123.45` | 17 | 7 | 10 |
| `0.0000123456789` | `$0.0000123457` | 9 | 6 | 3 |
| `0.0000000012345678901234` | `$0.00000000123457` | 14 | 6 | 8 |
| `2512.08` | `$2,512.08` | 6 | 6 | 0 |

Правило «что видно» повторяет `formatPrice`: от 1 — два знака после запятой, меньше 1 — шесть значащих цифр. Чтобы два правила не разошлись, есть тест-сверка: число «показанных» цифр линзы равно числу цифр в строке, которую вернул `formatPrice`.

Компонент — [`PriceLens`](../../apps/web/src/components/price-lens.tsx) на Base UI `Popover`:
- цена — `<button>`, а не `<span>` с обработчиком: работает с клавиатуры (Enter, пробел) и объявляется скринридером как кнопка;
- позиционирование, закрытие по Esc и нажатию вне блока, возврат фокуса на цену — от примитива;
- скринридер получает строку целиком через `aria-label`; разбивка на группы и подсветка скрыты от него (`aria-hidden`) — иначе цена зачитывалась бы по одной цифре;
- «Скопировать точное значение» кладёт в буфер строку из api, а не текст с пробелами между группами. Если браузер не дал доступ к буферу (страница открыта по http не с localhost), появляется сообщение, а не тишина.

### Доступность гида

- **Ловушка фокуса** — Base UI `Dialog` в режиме `trap-focus`: Tab ходит по кнопкам карточки и не уходит на страницу. Полный модальный режим не взят: он блокирует прокрутку, а гид сам прокручивает страницу к цели.
- **Клавиши** ← → листают шаги, Esc закрывает. Они действуют только при открытом гиде, поэтому под требование «однобуквенные клавиши должны отключаться» (WCAG 2.1.4) не попадают. Клавиши <kbd>G</kbd> из макета нет: ради неё пришлось бы делать экран настроек.
- **`aria-live`** объявляет только «Шаг 3 из 8. Заголовок» — текст шага читается из самой карточки. Живая область на весь текст заставила бы скринридер зачитывать каждый шаг дважды.
- **`prefers-reduced-motion`**: прокрутка к цели без анимации, переезд прожектора обнуляется общим правилом из `globals.css`.
- Кнопка «Назад» на первом шаге отключена, и фокус с неё переносится на «Далее»: с отключённой кнопки события клавиш не всплывают, и стрелки перестали бы работать.

### Положение карточки — чистая функция

[`placeCard`](../../apps/web/src/lib/tour/layout.ts) принимает три прямоугольника (цель, карточка, окно) и возвращает координаты. Порядок попыток: под целью → над целью → у того края окна, где свободнее, со сдвигом вбок. На телефоне карточка во всю ширину у края, дальнего от цели.

DOM в функции нет, поэтому каждый случай — обычный тест с числами: цель у нижнего края, цель во всё окно, окно уже 640 px. Компонент только измеряет (`getBoundingClientRect`) и применяет результат.

### Отметка «пройдено»

Гид открывается сам при первом открытии экрана. Отметка — строка `(user_id, tour)` в `web.db`: она привязана к пользователю, а не к браузеру, и переживает смену устройства.

- Список пройденных туров серверный layout читает из БД и отдаёт вместе со страницей. Отдельный запрос из браузера дал бы окно, в котором гид успевает открыться повторно.
- Пропуск (Esc, «Пропустить») отмечается так же, как прохождение: гид не навязывается дважды.
- `PUT /api/me/tours/{tour}` без тела: имя тура — в пути, повтор запроса безопасен.
- Тур экрана входа — исключение: пользователя ещё нет, отметка лежит в `localStorage`.

### Проверено

Тесты: 70 новых (линза — 18, отметки и маршруты — 18, шаги и геометрия — 34), всего 601. Один из них статический: у каждой цели шага есть элемент с таким `data-tour` в коде экранов — переименование атрибута не пройдёт незаметно.

В браузере на локальном стенде: линза на дашборде (фокус, Esc, возврат фокуса); четыре тура с клавиатуры; отметка после перезагрузки страницы; «Пройти гид заново»; Viewer видит 8 шагов дашборда вместо 9; телефон 375 px; светлая и тёмная темы.

Не проверено: успешное копирование из линзы (панель браузера не даёт доступ к буферу при программном нажатии — проверена ветка с сообщением об ошибке), плотность затемнения глазами (панель не отрисовывает на снимке полупрозрачный слой во весь экран), скринридеры, Firefox и Safari, собранный Docker-образ.

## Подводные камни

- **Быстрые нажатия во время перехода.** Первая версия запоминала запрошенный шаг сразу. Пока открывался раздел оператора, три нажатия «Далее» перескакивали два шага и трижды добавляли адрес в историю браузера. Теперь, пока шаг не на экране, нажатия игнорируются.
- **Цель выше окна.** Блок с длинной таблицей занимал весь экран — прожектор подсвечивал всё, то есть ничего. Цель перенесена на шапку блока.
- **Цели может не быть.** Шаг «Монета на паузе» указывает на метку, которой нет, если на паузе ни одной монеты. Шаг показывается по центру без прожектора; ждать появления цели дольше 300 мс на уже открытом экране незачем.
- **`clip-path` обрезает и нажатия, маска — нет.** Для выреза в затемнении это важно: через вырез нажатие дошло бы до страницы. Здесь затемнение — тень, а нажатия принимает отдельная прозрачная подложка.
- **Снимок экрана — не доказательство.** Панель браузера, в которой шла проверка, не рисует на снимке полупрозрачный слой во весь экран. Затемнение выглядело «слишком слабым»; контрольный `div` с тем же фоном показал то же самое — дефект снимка, а не кода. Сначала контрольный опыт, потом вывод.
- **`ALTER TABLE … DROP COLUMN` в SQLite** работает, если колонка не входит в индекс, внешний ключ и чужой `CHECK`. Собственный `CHECK` колонки удалению не мешает.
- **`data-tour` — контракт между данными и разметкой.** Без теста-сверки опечатка в имени цели дала бы шаг без прожектора, и заметили бы её только глазами.

## Вопросы на собеседовании

1. Почему линза считает значащие цифры по символам строки, а не через `Number`? → `Number` теряет цифры после 15–17-й: `0.0000000012345678901234` станет `1.2345678901234e-9`. Весь смысл линзы — показать то, что число не хранит.
2. Зачем цена сделана кнопкой, а не `<span onClick>`? → Кнопка получает фокус, срабатывает по Enter и пробелу и объявляется скринридером; `span` — только мышью.
3. Где хранить отметку «гид пройден» и почему не `localStorage`? → В БД на пользователя: отметка переживает смену браузера. `localStorage` остался только у тура экрана входа — там пользователя ещё нет.
4. Почему `PUT /api/me/tours/{tour}`, а не `POST /api/me/tours` с телом? → `PUT` идемпотентен: повтор при обрыве связи безопасен. Имя в пути — нет тела, нечего проверять.
5. Как протестировать положение карточки без браузера? → Вынести расчёт в чистую функцию от трёх прямоугольников; компонент только измеряет и применяет.
