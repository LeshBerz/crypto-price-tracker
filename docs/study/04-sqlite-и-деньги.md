# 04. SQLite, raw SQL и деньги в БД

> **Из курса** (урок «Работа с базой данных»): «Обработка ошибок при работе с транзакциями включает перехват исключений в блоке try/catch, чтобы при сбое любой операции внутри транзакции автоматически выполнить ROLLBACK, предотвращая частичное обновление данных».

## Простыми словами

Слой БД — это три кирпича и одно правило.

1. **Подключение** (`openDatabase`). Одно соединение `node:sqlite` на процесс плюс настройки: WAL (читатели не ждут писателя), `foreign_keys` (иначе `ON DELETE CASCADE` молча не работает), `busy_timeout`.
2. **Миграции** (`migrate`). SQL-файлы `0001_core.sql`, `0002_…`, применяются по порядку, каждый в своей транзакции. В таблице `schema_migrations` записана SHA-256 каждого файла. Если файл поменяли после применения, сервис не стартует. Аналогия — чек в магазине: товар можно вернуть новым чеком, но старый чек не переписывают.
3. **Транзакции** (`TransactionRunner`). `BEGIN` → работа → `COMMIT`, при ошибке — `ROLLBACK`. Соединение одно, поэтому транзакции встают в очередь.

Правило денег: **цена никогда не бывает float**. Она хранится строкой (`TEXT`), считается в `Decimal` на BigInt и уходит клиенту строкой. Float допустим только там, где нужен порядок, а не значение (`price_num` для `ORDER BY` и `MAX`).

## Как это в Nest → как в Express

| Nest + TypeORM / Prisma | В проекте |
|---|---|
| `TypeOrmModule.forRoot({ synchronize })` | `openDatabase()` + PRAGMA, без ORM (C1) |
| `typeorm migration:run`, таблица `migrations` | `migrate()` + `schema_migrations` с контрольной суммой — TypeORM её не хранит, а Flyway и Prisma хранят |
| `dataSource.transaction(async (em) => …)` | `TransactionRunner.run(async () => …)` |
| `@Column('decimal', { precision, scale })` + `decimal.js` | `TEXT` + генерируемая `REAL`-колонка + свой `Decimal` (C7: decimal.js нельзя) |

## Подводные камни

- **JS `number` в параметре `node:sqlite` — это REAL.** `7 / ?` с параметром `2` даёт `3.5`, а с `2n` — `3`. Бакеты по времени молча ломаются. Отсюда `sqlInt()` (тест в `database.test.ts`).
- **`PRAGMA busy_timeout` возвращает колонку `timeout`**, а не `busy_timeout`. Тест сначала упал на этом: имя колонки результата PRAGMA не всегда совпадает с именем PRAGMA.
- **CRLF и контрольная сумма.** Тот же файл после checkout на Windows с `autocrlf` — другие байты, другая SHA-256, и сервис отказался бы стартовать. Сумма считается по тексту с нормализованными переводами строк.
- **Параллельная и вложенная транзакции — не одно и то же.** Флаг `active` их путает: параллельный вызов был бы отвергнут как вложенный. Правильно — `AsyncLocalStorage`: вложенный вызов идёт из той же async-цепочки.
- **Сеть внутри транзакции.** Пока транзакция ждёт `await` с настоящим I/O, другие запросы того же соединения видят её незакоммиченные данные. Поэтому сначала запрос в CMC, потом транзакция (ADR 0015).
- **Ловушка округления.** 10 значащих цифр от `1.2345678901234e-9` — это `0.00000000123456789`, а не `…8901`: десятая цифра — ноль, и каноническая форма его отбрасывает. Сначала ошибся в ожидании теста, а не код.
- **`-0`.** Паттерн контракта `^-?(0|…)` формально пропускает `-0`. `Decimal` его не производит: у BigInt нет отрицательного нуля.

## Вопросы на собеседовании

1. Почему цены не во float и как тогда сортировать и искать максимум в SQLite? → Float теряет точность и даёт `0.1 + 0.2 ≠ 0.3`. Точная строка `TEXT` — источник истины. Рядом генерируемая `REAL`-колонка, она нужна только для порядка, а наружу отдаётся точная строка найденной записи.
2. Что такое HALF_EVEN и зачем он нужен? → Ровно половина округляется к чётной цифре: 2.5 → 2, 3.5 → 4. При многих округлениях ошибки взаимно гасятся, а HALF_UP всегда тянет вверх.
3. Зачем в миграциях контрольная сумма и почему только вперёд? → Чтобы БД и код не разошлись молча: изменённая применённая миграция останавливает старт. Откат — новой миграцией, потому что данные назад не «отматываются».
4. Синхронный драйвер и одно соединение: как не сломать транзакции в async-коде? → Очередь транзакций, запрет вложенности через `AsyncLocalStorage`, никакой сети внутри транзакции.
5. Почему целые параметры передаёшь как BigInt? → `node:sqlite` превращает JS `number` в REAL, и целочисленная арифметика в SQL становится дробной.
