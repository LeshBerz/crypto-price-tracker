# 17. Web: карточка монеты, график и курсорная история

> **Опорный принцип** (тема «Авторизация, API и внешние источники», по карте тем `course-map.md`): «…данные валидировать → трансформировать → нормализовать».

Карточка монеты — экран, где этот конвейер виден целиком: ответ api (бакеты OHLC строками) преобразуется в точки графика, событие потока — в правку последней свечи, страницы истории — в одну таблицу. Каждое преобразование — чистая функция с тестом.

## Простыми словами
График — это кардиограмма на бумажной ленте. Ленту (историю за период) печатают один раз. Дальше самописец дорисовывает только последний зубец, а не перепечатывает ленту на каждый удар сердца. Если пациента отключали от прибора, на ленте остаётся пустой участок — его не дорисовывают «по смыслу».

- **Агрегаты** (`getPriceAggregates`) — лента: бакеты `open / close / min / max` за период. Интервал бакета × период ограничены 1000 бакетов.
- **`price.updated`** — самописец: правит последнюю свечу в кэше, график вызывает `series.update()`.
- **История** (`listPriceHistory`) — сырые точки страницами по курсору.

## Как это в Nest → как в Next.js и React
| Задача | Nest (сервер) | Здесь (браузер) |
|---|---|---|
| Проверка параметра пути | `ParseIntPipe` → 400 | [`page.tsx`](<../../apps/web/src/app/(app)/coins/[id]/page.tsx>): регулярное выражение → `notFound()` (ответ 404) |
| Проверка сочетания параметров | `class-validator` в DTO → 400 | [`intervals.ts`](../../apps/web/src/lib/coin/intervals.ts): `comboIssue` — кнопка неактивна **до** запроса |
| Преобразование ответа | `ClassSerializerInterceptor`, mapper | [`chart-data.ts`](../../apps/web/src/lib/coin/chart-data.ts): бакеты → точки графика |
| Общий ресурс на всё приложение | провайдер-синглтон в модуле | `StreamProvider` в layout: одно соединение на вкладку |
| Сторонняя императивная библиотека | обёртка-провайдер с `onModuleInit` / `onModuleDestroy` | компонент с `useEffect`: создание, приведение к данным, удаление в cleanup |
| Пагинация | `limit` + курсор в DTO | `useInfiniteQuery`: параметр страницы — курсор из ответа |

## В проекте

### Интервал × период: проверка до запроса
[`intervals.ts`](../../apps/web/src/lib/coin/intervals.ts), [ADR 0007](../adr/0007-aggregates-and-rollups.md). Api отвечает 400, если `(to − from) / interval > 1000`. Клиент повторяет это правило заранее:

| | 24 ч | 7 д | 30 д | 1 год |
|---|---|---|---|---|
| **1 ч** | 24 | 168 | 720 | 8 760 — нельзя |
| **4 ч** | 6 | 42 | 180 | 2 190 — нельзя |
| **1 д** | 1 — нельзя | 7 | 30 | 365 |
| **1 нед** | меньше 1 — нельзя | 1 — нельзя | около 4 | около 52 |

Недоступная кнопка помечена `aria-disabled`, а не `disabled`: она остаётся в обходе клавиатурой и по нажатию показывает причину («1 ч × 1 год — это 8 760 бакетов…»).

Начало периода выравнивается по границе бакета (`periodFrom`): иначе первый бакет собрался бы из части часов и выглядел бы полноценной свечой. Недели считаются с понедельника — `bucketStartOf` повторяет формулу api (эпоха Unix — четверг, сдвиг на три дня).

Дублирование правила на клиенте — осознанное: источник правды остаётся в api (он всё равно ответит 400), а клиент лишь не даёт нажать заведомо отказную кнопку. Тест перечисляет все недоступные сочетания списком — изменение предела сломает его.

### Бакеты → точки графика
[`chart-data.ts`](../../apps/web/src/lib/coin/chart-data.ts).

- Свеча: `open`, `high = max`, `low = min`, `close`; линия — по `close`. Время — секунды Unix.
- **Пропуски.** Api не отдаёт пустые бакеты, а шкала времени графика порядковая: без пропусков свечи до и после сбоя встали бы вплотную. `toChartPoints` вставляет точки без значения — место на шкале занято, ничего не нарисовано. Линия пропуск не показывает (соединяет соседние точки) — об этом сказано в подписи под графиком.
- **Шаг шкалы** (`priceStep`): цент для цен от 1, шестая значащая цифра — для мелких. Без него цена `0.0000000012` дала бы шкалу из одних нулей.

### Где цена становится числом
[ADR 0012](../adr/0012-web-charts-and-ui-kit.md), поправка 6. Lightweight Charts принимает только `number`. Правило проекта «цены не считаются во float» не нарушено, потому что граница проведена по canvas:

| Что на экране | Откуда значение |
|---|---|
| Положение свечи, деления шкалы цен | `Number(строка)` — пиксели и округлённые координаты |
| Подсказка под курсором (O / H / L / C, изменение) | строки бакета из ответа api: бакет находится по времени под курсором |
| Сводка, шапка, таблица истории | строки api, `Intl.NumberFormat` |
| Новый минимум и максимум свечи | `compareDecimal` — сравнение строк |

Double хранит 15–17 значащих цифр, а высота графика — сотни пикселей: погрешность на много порядков меньше пикселя. Точное значение пользователь читает в подсказке, и оно — не из float.

### Обёртка над императивной библиотекой
[`price-chart.tsx`](../../apps/web/src/components/coin/price-chart.tsx). React описывает «что должно быть», Lightweight Charts — «сделай это». Компонент их стыкует двумя эффектами:

1. **Создание** (один раз): `createChart`, подписка на перемещение курсора, наблюдатель за атрибутом темы; в cleanup — `chart.remove()`.
2. **Приведение к данным** (на каждое изменение точек или вида): `planSeriesUpdate` сравнивает нарисованное с новым и возвращает план:

| Что изменилось | План | Вызов |
|---|---|---|
| ничего | `none` | — |
| последняя точка или новые точки справа | `update` | `series.update()` для каждой |
| другой период, правка в середине, первая отрисовка | `reset` | `series.setData()` + `fitContent()` |

`update` не сбрасывает масштаб и прокрутку пользователя — поэтому тик цены не дёргает график.

Тема: canvas не понимает переменные CSS. Цвета читаются через `getComputedStyle` и передаются значениями; `MutationObserver` на атрибуте `data-theme` перекрашивает график без пересоздания.

Клавиатура: стрелки влево и вправо перемещают выбранный бакет, `Home` / `End` — в начало и конец, `Escape` — сброс. Подсказка лежит в DOM (а не на canvas) и читается скринридером.

### Один поток на вкладку
[`stream-provider.tsx`](../../apps/web/src/components/stream-provider.tsx), [ADR 0012](../adr/0012-web-charts-and-ui-kit.md), поправки 7–8. В C3 соединение открывал дашборд. Теперь оно живёт в layout группы `(app)`:

- переход дашборд ↔ карточка соединение не переоткрывает;
- `session.expired` срабатывает на любом экране;
- экраны не подписываются на поток: событие пишется в **кэш запросов**, а компоненты читают кэш. Кэш — шина между потоком и экранами.

Следствие: фоновый перезапрос ([`queries.ts`](../../apps/web/src/lib/dashboard/queries.ts), `refreshInBackground`) теперь проверяет, есть ли у запроса наблюдатель. На экране — перечитать; не на экране — пометить устаревшим. Иначе карточка каждые 5 минут тянула бы данные дашборда.

### Событие → данные карточки
[`live-updates.ts`](../../apps/web/src/lib/coin/live-updates.ts), [`stream-events.ts`](../../apps/web/src/lib/dashboard/stream-events.ts).

| Событие | Что происходит на карточке |
|---|---|
| `price.updated` | шапка: новая цена, «устарела» снято; график: `close`, `min`, `max` последней свечи (или новая свеча, если начался новый бакет) — во всех загруженных сочетаниях интервала и периода; история: точка первой строкой. Запросов нет |
| `sync.finished` | фоном перечитываются монета и график на экране: среднее, изменение, число точек и сводку считает сервер |
| `watchlist.changed` | фоном перечитывается монета. Ответ 404 → экран «Монета не отслеживается» |
| поток переподключился | перечитывается всё, история — одной первой страницей |

Почему клиент не пересчитывает среднее и изменение сам: это десятичная арифметика с правилами округления api (HALF_EVEN, 10 значащих цифр). Вторая реализация формулы — второй источник правды. Наблюдённые цены (`open / close / min / max`) обновляются точно — сравнением строк.

### История: курсор, а не номер страницы
[`queries.ts`](../../apps/web/src/lib/coin/queries.ts), `historyQuery`, [`history-table.tsx`](../../apps/web/src/components/coin/history-table.tsx).

- `useInfiniteQuery`: `getNextPageParam` возвращает `nextCursor` из ответа; `null` — страниц больше нет.
- Новая точка из потока дописывается в начало первой страницы. Курсор от этого не ломается: он указывает на позицию в данных («старше такой-то точки»), а не на номер строки. При пагинации по `OFFSET` та же вставка сдвинула бы страницы и дала бы дубль.
- `mergeHistoryPages` отбрасывает дубли по времени котировки (в БД оно уникально в пределах монеты): точка может прийти и событием, и ответом api.
- После переподключения потока история перечитывается **одной первой страницей** (`fetchInfiniteQuery` с `pages: 1`). Обычное перечитывание бесконечного запроса запрашивает заново каждую открытую страницу; `staleTime: Infinity` его отключает.

### 404: два пути к одному экрану
- Адрес не похож на id (`/coins/abc`) → `notFound()` в серверном компоненте, HTTP-ответ 404.
- Id корректный, монеты нет (или её удалили, пока карточка открыта) → api отвечает Problem `not-found`, запрос монеты получает ошибку 404, компонент показывает тот же экран. HTTP-ответ страницы при этом 200: данные карточка запрашивает из браузера, как и дашборд.

### Данные для проверки
[`seed-price-history.ts`](../../apps/web/scripts/seed-price-history.ts). Стаб CoinMarketCap отдаёт одну и ту же котировку, а тариф Basic не отдаёт прошлые цены — история сама не накопится. Dev-скрипт дописывает перед самой ранней точкой каждой монеты случайное блуждание (с зерном — повторяемо) и пятичасовой пропуск; затем `rollups:rebuild` пересобирает свёртки. В образ и CI скрипт не входит.

## Подводные камни
- **`fitContent()` при нулевой ширине сжимает ряд в полоску у правого края.** `autoSize` узнаёт размер контейнера асинхронно (`ResizeObserver`), а данные приходят раньше. Размер передаётся в `createChart` сразу. Найдено на первом же снимке экрана.
- **Линия не разрывается на точках без значения.** Пропуск данных виден только в режиме свечей; подпись под графиком это говорит прямо.
- **`series.update()` падает на точке левее последней.** `planSeriesUpdate` отдаёт в `update` только хвост ряда; всё остальное — `setData`.
- **Локальное время на шкале — ловушка.** Сдвиг меток под часовой пояс при переводе часов даёт две точки с одним временем, а график на дублях бросает исключение. Шкала оставлена в UTC с пометкой.
- **Правило линтера `react-hooks/immutability`** запрещает менять объект, прочитанный из `ref.current`, внутри эффекта. Нарисованные точки хранятся в отдельном `ref`, меняется сам `current`.
- **Имя состояния `setInterval`** затенило бы глобальную функцию — сеттер назван `selectInterval`.
- **Ключи запросов с общим корнем.** `['cryptocurrencies']` (список) и `['cryptocurrencies', id]` совпали бы по префиксу: пометка списка устаревшим задела бы карточки. У карточки свои корни: `coin`, `coin-aggregates`, `coin-history`.
- **Сид знает схему БД api.** Изменится таблица `price_history` — скрипт сломается. Это цена dev-инструмента; в рантайме web в БД api не ходит.

## Вопросы на собеседовании
1. **Правило «не считаем цены во float», а график принимает `number`. Это нарушение?** → Нет: в число превращаются только координаты на canvas. Всё, что пользователь читает как значение (подсказка, сводка, история), — строки api. Погрешность double на порядки меньше пикселя.
2. **Зачем клиент повторяет проверку «не больше 1000 бакетов», если api и так ответит 400?** → Чтобы не дать нажать заведомо отказную кнопку и объяснить причину. Источник правды — api; тест на клиенте перечисляет недоступные сочетания.
3. **Почему в истории курсор, а не `page=2`?** → В начало списка постоянно добавляются точки. `OFFSET` сдвинул бы страницы: дубли или пропуски. Курсор указывает на позицию в данных.
4. **Как график обновляется от события и почему не перерисовывается целиком?** → Событие правит последнюю свечу в кэше; компонент сравнивает нарисованное с новым и вызывает `series.update()`. Масштаб пользователя не сбрасывается.
5. **Почему соединение SSE одно на вкладку и как экраны узнают о событиях?** → Провайдер в layout держит поток; события пишутся в кэш запросов, экраны читают кэш. Фоновые перезапросы — только для данных на экране.
