# 21. Качество интерфейса: общие компоненты, состояния, доступность и временный пароль

> **Из курса** ([конспект](../course/course-map.md), ценности и критерии оценки): «Фокус на результат, а не на процесс»; оценивают «качество, самостоятельность, внимательность к граничным случаям, скорость, результат».

## Простыми словами

После C1–C6 каждый экран работал, но был собран отдельно: свои отступы таблиц, свой скелетон (точнее, один чужой на всех), подсказки через атрибут `title`, пояснения серым абзацем под полем. По отдельности это мелочи, вместе — ощущение «набора форм».

C11 — не новые функции, а один слой общих компонентов и правил, на который переведены все экраны. Аналогия из бэкенда: вместо того чтобы в каждом обработчике по-своему собирать ответ с ошибкой, вводится один `problem()` — и формат становится одинаковым везде. Здесь то же самое, только для разметки.

Заодно закрыты две настоящие ошибки, найденные при обходе экранов: бесконечный редирект при отклонённом ключе api и бессрочный временный пароль.

## Как это в Nest → как в Express → как в React

| Идея | Nest | Express | Здесь (React) |
|---|---|---|---|
| Общее правило в одном месте | глобальный pipe / interceptor | middleware | общий компонент: `Field`, `Panel`, `Timestamp` |
| Обязательное условие до обработчика | guard | middleware перед роутом | проверка в `enter()` и в серверном layout |
| Единый формат ошибки | exception filter | error-middleware | `LoadError`, ошибка у поля в `Field` |

Обязательная смена пароля — классический guard: условие проверяется до любого обработчика, а не в каждом из них.

### «i» вместо текста — не везде

Требования к вводу («латинские буквы и цифры, до 15 символов», «не короче 12 символов») остались на виду. Причина — WCAG 3.3.2 (подписи и инструкции): требование нужно прочитать **до** ввода, а не после ошибки. За значок убран только текст «почему так»: что символы в CoinMarketCap не уникальны, откуда берётся пароль, сколько живёт сессия.

Сам значок — кнопка с `Popover`, а не подсказка по наведению. У подсказки по наведению нет способа открыться на сенсорном экране.

### Отключённая кнопка, которая объясняет причину

Обычная `disabled`-кнопка не получает ни фокуса, ни наведения — подсказку на ней не увидит никто. В [`ActionButton`](../../apps/web/src/components/account/users-panel.tsx) запрещённое правилом действие («последний оператор», «свой пароль меняется в профиле») рендерится с `focusableWhenDisabled`: Base UI ставит `aria-disabled` вместо `disabled`, кнопка остаётся в порядке Tab и показывает причину.

### Движение

Три длительности и одна кривая — токены в [`globals.css`](../../apps/web/src/app/globals.css): `--duration-fast` (отклик на наведение), `--duration-base` (раскрытие блока, строка, диалог), `--duration-slow` (уведомление). Правило `prefers-reduced-motion` там же обнуляет длительности всех анимаций и переходов разом (WCAG 2.3.3, ADR 0018).

Появление строки (`animate-row-in`) сделано, исчезновение — нет: для него нужно держать элемент в DOM после удаления из данных, это отдельный механизм (или библиотека). Решение — не тащить зависимость ради одного эффекта.

### Бесконечный редирект при 401 от api

Найдено на стенде: api был запущен со старыми ключами и отвечал web 401. BFF передавал 401 браузеру как есть, клиент считал сессию истёкшей и уходил на `/login?reason=expired`, а страница входа видела живую сессию и возвращала на дашборд. По кругу.

Причина — смешение двух разных «не авторизован»: пользователь перед web и web перед api. Исправление — [`relayOrRejectKey`](../../apps/web/src/server/bff/bff-http.ts): 401 от api превращается в 502 `upstream-rejected-key` со строкой уровня `error` в логе. Сессия пользователя к этому моменту уже проверена, значит 401 от api может означать только ошибку настройки.

### Обязательная смена временного пароля

Пароль при создании пользователя и сбросе создаёт сервер и показывает оператору один раз (ADR 0016, поправка 29). До C11 он жил бессрочно: оператор знал действующий пароль пользователя.

| Слой | Что сделано |
|---|---|
| Схема | миграция [`0003`](../project/schema/web_0003_password_change.sql): `users.must_change_password`, у существующих строк — 0 |
| Запись | `create` и `resetPassword` ставят 1, `changeOwnPassword` — 0 ([`user-admin.ts`](../../apps/web/src/server/user-admin.ts)) |
| Сессия | признак читается тем же запросом, что и роль ([`sessions.ts`](../../apps/web/src/server/sessions.ts)) — отдельной выборки нет |
| Запрет | `/api/admin/*`, `/api/me/*`, BFF и поток отвечают 403 `password-change-required`; открыты только `PUT /api/me/password` и выход |
| Экран | layout группы `(app)` перенаправляет на [`/password`](../../apps/web/src/app/password/page.tsx) — та же форма, что в профиле |

Запрет стоит на сервере в трёх местах, а не только редиректом в layout: редирект — удобство, запрос мимо экрана он не остановит.

### Проверено

Тесты: 27 новых ([`temporary-password.test.ts`](../../apps/web/tests/temporary-password.test.ts), [`interface.test.ts`](../../apps/web/tests/interface.test.ts), случаи 401 → 502 в тестах BFF и потока), всего 531. В браузере на локальном стенде: все экраны под Operator, дашборд и запрет раздела оператора под Viewer, сценарий «создан пользователь → вход с выданным паролем → экран смены → вход с новым». Тёмная тема и 375 px — на watchlist; горизонтальной прокрутки нет.

Не проверено: плавность анимаций глазами (панель браузера, в которой шла проверка, не отрисовывала кадры — `requestAnimationFrame` не вызывался), скринридеры, Firefox и Safari.

## Подводные камни

- **`title` — не подсказка.** С клавиатуры и на телефоне атрибут недоступен, скринридеры читают его непоследовательно. Он остался в одном месте — плитки сводки на карточке монеты, где у блока нет своего действия.
- **Подсказка на `disabled`-кнопке не работает** — нужен `aria-disabled` и фокус.
- **Скелетон чужой формы хуже, чем его отсутствие:** экран «прыгает» дважды — когда появляется заглушка и когда её сменяет содержимое другой формы.
- **Редирект в layout — не защита.** Сервер обязан отказать сам: layout не выполняется для `fetch` из консоли.
- **Статус от соседнего сервиса нельзя отдавать как свой.** 401 от api для браузера означает совсем другое, чем для BFF.
- **`ALTER TABLE … ADD COLUMN … NOT NULL` в SQLite требует `DEFAULT`** — иначе существующим строкам нечего записать.
- **Хэш для цвета должен перемешивать.** Первый вариант (полиномиальный хэш по модулю 360) давал BTC и ETH тон с разницей 16°; поймал тест. Заменён на FNV-1a.

## Вопросы на собеседовании

1. Почему пояснения нельзя целиком убрать за значок «i»? → Требование к вводу нужно до ввода (WCAG 3.3.2); за значком — только «почему так».
2. Чем `aria-disabled` отличается от `disabled` и когда нужен первый? → `disabled` убирает элемент из фокуса и событий; `aria-disabled` оставляет — можно объяснить причину.
3. BFF получил 401 от api. Что отдать браузеру и почему не 401? → 502: это ошибка настройки web, а не истёкшая сессия пользователя; иначе клиент уйдёт на вход по кругу.
4. Где должна стоять проверка «сначала смени пароль» — в layout или в обработчиках? → В обоих, но защита — в обработчиках: layout не выполняется для прямых запросов.
5. Как отключить все анимации для пользователя, которому они мешают? → `prefers-reduced-motion: reduce` и одно правило, обнуляющее длительности.
