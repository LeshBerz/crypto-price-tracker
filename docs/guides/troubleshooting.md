## Установка зависимостей

### `npm error code EBADENGINE`

**Причина.** Активная версия Node.js меньше 24.15. Проверка: `node -v`.

**Что сделать.** Включить Node.js 24 — [Локально → Node.js 24](local.md#1-nodejs-24). Менеджер версий действует на терминал, в котором выполнен `fnm use`: в новом окне версия может снова оказаться системной, пока fnm не подключён в профиле оболочки.

### `npm error code EPERM … unlink … .node` (Windows)

**Причина.** `npm ci` сначала удаляет `node_modules`, а файл занят работающим процессом Node.js — чаще всего dev-сервером web (`next-swc.win32-x64-msvc.node`) или api в режиме `--watch`. Windows не даёт удалить открытый файл.

**Что сделать.** Остановить все процессы проекта (`Ctrl+C` в их терминалах) и повторить `npm ci`. Посмотреть, какие процессы Node.js ещё работают, в PowerShell:

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" | Select-Object ProcessId, CommandLine
```

### `Cannot find package 'express'` и подобные

**Причина.** Каталог `node_modules` неполон: предыдущая установка прервалась (например, ошибкой `EPERM` выше) уже после удаления части пакетов.

**Что сделать.** Устранить причину сбоя и выполнить `npm ci` до конца.

## Старт api

### `.env not found. Continuing without it.`

**Причина.** Не ошибка. Строка запуска читает два файла: корневой `.env` и необязательный `apps/api/.env`. Сообщение относится ко второму. В режиме `--watch` оно печатается дважды — наблюдающим процессом и самим сервером.

**Что сделать.** Ничего. Если корневой `.env` действительно не прочитан, следом появится ошибка конфигурации с именем переменной.

### `Некорректная конфигурация: CMC_API_KEY: обязательна`

**Причина.** Файла `.env` в корне нет или переменная в нём пуста.

**Что сделать.** [Локально → Файл окружения](local.md#3-файл-окружения). Для стаба подойдёт значение `stub-cmc-key`.

### Порт 3000 занят (`EADDRINUSE`, `http server failed`)

**Причина.** На порту уже работает другой экземпляр: контейнер api из `docker compose` (у него `restart: unless-stopped`) или прежний dev-процесс.

**Что сделать.** `docker compose down` и остановить прежние процессы. Либо задать другой порт в `.env`: `PORT=3005`.

### Нет каталога миграций

**Причина.** api запущен не из каталога `apps/api`: миграции и относительный `DATABASE_PATH` отсчитываются от текущего каталога.

**Что сделать.** Запускать через `npm run dev -w @cpt/api` из корня — npm сам переходит в каталог пакета.

## Запросы к api

### 401 на любой запрос

**Причина.** Ключ не передан, передан с опечаткой или выпущен для другой базы. У Docker и локального запуска базы разные: ключ, выпущенный в контейнере, локальному api неизвестен, и наоборот. После сброса базы прежние ключи тоже не действуют.

**Что сделать.** Выпустить ключ для того экземпляра, который запущен: `docker compose run --rm api node dist/cli/keys.js create …` или `npm run keys:create -w @cpt/api -- …`.

### 403

**Причина.** Ключ роли viewer на операции записи.

**Что сделать.** Выпустить ключ с `--role operator`.

### 422 при добавлении монеты

**Причина.** Источник цен не знает символ. Стаб знает только BTC, ETH и MEME.

**Что сделать.** Для проверки на стабе использовать эти три символа; для остальных — [настоящий CoinMarketCap](README.md#стаб-и-настоящий-coinmarketcap).

### 503 при добавлении монеты, синхронизация завершается ошибкой

**Причина.** Источник цен недоступен. Частые случаи: `CMC_BASE_URL=http://localhost:4010`, а стаб не запущен; эта же строка осталась в `.env` перед `docker compose up` (в контейнере `localhost` — сам контейнер); настоящий CoinMarketCap отклонил ключ.

**Что сделать.** Проверить `CMC_BASE_URL` и `CMC_API_KEY`; состояние интеграции и последняя ошибка — `GET /api/v1/system/cmc`. Чтение цен при этом продолжает работать: они отдаются из БД с признаком `isStale`.

### В PowerShell не работает пример с `curl`

**Причина.** В Windows PowerShell `curl` — псевдоним команды `Invoke-WebRequest` с другими параметрами.

**Что сделать.** Вызывать `curl.exe` либо выполнять запросы из Swagger UI.

## Веб-клиент

### web не стартует и называет переменную

**Причина.** В `.env` не заданы ключи api (`BOOTSTRAP_VIEWER_KEY`, `BOOTSTRAP_OPERATOR_KEY`) или пара `WEB_BOOTSTRAP_LOGIN` и `WEB_BOOTSTRAP_PASSWORD_HASH`.

**Что сделать.** [Локально → Веб-клиент](local.md#веб-клиент).

### `The "…" variable is not set` и `web не запущен: WEB_BOOTSTRAP_PASSWORD_HASH`

**Причина.** Хэш в `.env` записан без одинарных кавычек. Docker Compose принимает каждый фрагмент `$…` внутри хэша за имя переменной, не находит её и подставляет пустую строку — об этом и предупреждение. В контейнер попадает обрезанный хэш, web отказывается стартовать, а compose перезапускает его снова и снова. Страница <http://localhost:3001> при этом не открывается.

**Что сделать.** Остановить: `docker compose --profile web down`. Взять хэш в одинарные кавычки и запустить заново:

```dotenv
WEB_BOOTSTRAP_PASSWORD_HASH='scrypt$17$8$1$…'
```

### 401 при входе с верным паролем

**Причина.** Первый оператор создаётся при старте, только если такого логина ещё нет. Если база web осталась от прошлого запуска, в ней прежний хэш, и новый `WEB_BOOTSTRAP_PASSWORD_HASH` на него не влияет. Вторая причина — хэш в `.env` записан без одинарных кавычек, и знаки `$` были подставлены как переменные.

**Что сделать.** Войти прежним паролем либо сбросить базу web: локально — удалить `apps/web/data`, в Docker — `docker compose --profile web down -v`.

### «API недоступен» на экранах

**Причина.** web не может обратиться к api: api не запущен, слушает другой порт или `API_BASE_URL` указывает не туда.

**Что сделать.** Проверить <http://localhost:3000/health/ready> и значение `API_BASE_URL`.

### Пользователи или монеты «пропали»

**Причина.** Пути к базам относительные. Запуск другой командой или из другого каталога создаёт вторую базу.

**Что сделать.** Запускать одними и теми же командами: `npm run dev -w @cpt/api`, `npm run dev -w @cpt/web`.

## Docker

### Изменения в `.env` не применились

**Причина.** Переменные подставляются при создании контейнера.

**Что сделать.** `docker compose up` ещё раз: compose пересоздаст контейнер с новыми значениями.

### Остались данные прошлого запуска

**Причина.** Базы лежат в томах `api-data` и `web-data` и переживают `docker compose down`.

**Что сделать.** `docker compose --profile web down -v`.
