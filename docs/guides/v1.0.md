## Запуск

Нужен только Docker. Сервис ходит в стаб CoinMarketCap из того же compose: ключ CMC и интернет не нужны. Запуск и проверка занимают около пяти минут, большая часть — сборка образа.

```bash
git checkout v1.0
```

```bash
docker compose up --build
```

После переключения на тег в каталоге лежит README версии 1.0 — дальше можно идти по нему. Гайдов из `docs/guides/` в теге нет: они написаны позже.

## Проверка

1. В логах есть строки `database ready`, `http server listening` и `sync finished`.
2. Выпустить API-ключ (во втором терминале). Ключ печатается один раз, в БД хранится только хэш:

   ```bash
   docker compose run --rm api node dist/cli/keys.js create --name local --role operator
   ```

3. Открыть Swagger UI — <http://localhost:3000/docs> → **Authorize** → вставить ключ.
4. `POST /api/v1/cryptocurrencies` с телом `{"symbol":"BTC"}` → 201. Стаб знает BTC, ETH и MEME.
5. `POST /api/v1/sync-runs` → 202.
6. `GET /api/v1/prices` → цена BTC строкой.

Соответствие требованиям ТЗ коду и тестам — [`docs/project/requirements.md`](../project/requirements.md), тесты по каждому эндпоинту — [`docs/project/test-matrix.md`](../project/test-matrix.md).

## Остановка и возврат к main

`Ctrl+C` в терминале с compose, затем:

```bash
docker compose down -v
```

```bash
git checkout main
```

Флаг `-v` удаляет том с базой: версия 1.0 и `main` используют один и тот же том, без удаления в `main` останутся монеты и ключи этого запуска.

## Чем main отличается от версии 1.0

Эндпоинты из ТЗ, схема БД и зависимости api после тега не менялись.

| Что | Версия 1.0 | `main` | Где описано |
|---|---|---|---|
| Контракт api | `1.0.0` | `1.1.0`: в ответе `GET /api/v1/system/cmc` добавлен блок `schedule` (состояние планировщика, интервал, время следующего запуска) | [ADR 0014, поправка от 12.10](../adr/0014-api-contract.md#поправка-от-1210) |
| Файл окружения для npm-скриптов | `apps/api/.env` (`cp .env.example apps/api/.env`) | `.env` в корне, общий для compose, api и web | [ADR 0004](../adr/0004-c7-interpretation-and-dev-tooling.md) |
| Тесты api | 726 | 727: тесты блока `schedule` | [матрица тестов](../project/test-matrix.md) |
| Веб-клиент | нет | `apps/web`, включается профилем compose; 601 тест, отдельный job в CI | [README web](../../apps/web/README.md), [снимки экрана](../screenshots/README.md) |
| Гайды по запуску | в README | каталог `docs/guides/` | [Гайды](README.md) |

Запуск без Docker на версии 1.0 описан в её README; на `main` — в гайде [Локально через npm](local.md).

## Что не сделано и не проверено

| Что | Состояние |
|---|---|
| Формат живого ответа CoinMarketCap | Автоматические тесты идут против стаба, который повторяет формат CMC по документации ([ADR 0006](../adr/0006-price-precision.md)). На `main` сервис запускался в Docker с настоящим CoinMarketCap: добавление монеты и синхронизация по расписанию прошли без ошибок. Прицельный скрипт `npm run smoke:cmc` не запускался |
| Остановка по `SIGTERM` на Windows | Тест с настоящим сигналом выполняется на Linux и в CI; на Windows сигнал не доставляется, тест пропускается |
| Алерты, профиль `platform` | Спроектированы в ADR, не реализованы — в ТЗ их нет |
| e2e-сценарии веб-клиента в браузере | Не написаны. Веб-клиент в версию 1.0 не входит |
