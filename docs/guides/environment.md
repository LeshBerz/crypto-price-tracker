## Один файл

Файл окружения один — `.env` в корне репозитория. Шаблон со всеми переменными и комментариями — [`.env.example`](../../.env.example). В git файл `.env` не попадает.

```bash
cp .env.example .env
```

Команда перезаписывает существующий `.env` без вопроса.

Решение и обоснование — [ADR 0004, поправка от 12.10](../adr/0004-c7-interpretation-and-dev-tooling.md).

## Кто и как его читает

| Кто | Как | Что берёт |
|---|---|---|
| `docker compose` | Сам читает `.env` рядом с `docker-compose.yml` и подставляет значения в `${…}` | Только переменные, перечисленные в `docker-compose.yml`. Файл в контейнер не копируется |
| npm-скрипты api | Флаг Node.js `--env-file-if-exists=../../.env` в строке запуска ([`apps/api/package.json`](../../apps/api/package.json)) | Все переменные файла попадают в `process.env` |
| Веб-клиент | Модуль [`root-env.ts`](../../apps/web/src/server/root-env.ts) разбирает файл функцией `util.parseEnv` | Только свои переменные. В `process.env` файл не загружается: ключ CoinMarketCap в процессе web не появляется |

Библиотеки `dotenv` в проекте нет: файл читает сам Node.js.

Следом за корневым файлом npm-скрипты api читают необязательный `apps/api/.env` — он переопределяет общий. Если его нет, Node.js печатает `.env not found. Continuing without it.` Это не ошибка.

## Приоритет значений

От сильного к слабому:

1. Переменные процесса — заданные в терминале, в CI или блоком `environment` в compose.
2. `apps/api/.env` (для api), `apps/web/.env.local` (для web) — если есть.
3. `.env` в корне.
4. Значение по умолчанию в коде.

## Переменные api

Валидация — [`apps/api/src/config.ts`](../../apps/api/src/config.ts).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CMC_API_KEY` | — (обязательна) | Ключ CoinMarketCap. Только из окружения (D-4), уходит только заголовком запроса. В compose по умолчанию — ключ стаба |
| `CMC_BASE_URL` | локально — `https://pro-api.coinmarketcap.com`; в compose — стаб | Адрес CoinMarketCap или стаба |
| `CMC_TIMEOUT_MS` | `10000` | Таймаут запроса к CMC (C5) |
| `SYNC_INTERVAL_MS` | `300000` | Интервал фоновой синхронизации, не меньше 180 000 (квота CMC Basic) |
| `DATABASE_PATH` | `./data/cpt.db` | Файл SQLite, путь от каталога `apps/api`; `data/` в `.gitignore` (C3). В Docker не используется — там том `/data` |
| `PORT` | `3000` | Локально — порт процесса; в compose — порт на хосте |
| `LOG_LEVEL` | `info` | `debug` · `info` · `warn` · `error`; логи — JSON в stdout |
| `BOOTSTRAP_VIEWER_KEY`, `BOOTSTRAP_OPERATOR_KEY` | — | Необязательные готовые API-ключи: при старте в БД пишется их SHA-256. Нужны веб-клиенту и скрипту `smoke` |

Bootstrap-ключ — это `cpt_` + 43 символа base64url. Сгенерировать:

```bash
node -e "console.log('cpt_' + require('node:crypto').randomBytes(32).toString('base64url'))"
```

## Переменные веб-клиента

Валидация — [`apps/web/src/server/config.ts`](../../apps/web/src/server/config.ts).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_BASE_URL` | `http://localhost:3000` | Адрес api: только origin, без пути. В compose задаётся самим compose |
| `API_VIEWER_KEY` | значение `BOOTSTRAP_VIEWER_KEY` | Ключ api роли viewer |
| `API_OPERATOR_KEY` | значение `BOOTSTRAP_OPERATOR_KEY` | Ключ api роли operator. Должен отличаться от ключа viewer |
| `API_TIMEOUT_MS` | `10000` | Сколько ждать ответа api; дольше — 504 |
| `WEB_DATABASE_PATH` | `./data/web.db` | SQLite с пользователями и сессиями, путь от каталога `apps/web` |
| `WEB_BOOTSTRAP_LOGIN` | — | Логин первого оператора. Создаётся при старте, если такого логина ещё нет |
| `WEB_BOOTSTRAP_PASSWORD_HASH` | — | Хэш его пароля (`npm run hash-password -w @cpt/web`). В одинарных кавычках |
| `WEB_TRUST_PROXY` | `false` | `true`, если перед web стоит обратный прокси |
| `WEB_PORT` | `3001` | Порт web на хосте в compose. Локально web слушает 3001 |

## Что будет, если переменной нет

- **Обязательной переменной нет или значение некорректно** — сервис не стартует. Сообщение перечисляет все проблемы сразу и называет переменные; значения в сообщение не попадают:

  ```text
  Некорректная конфигурация:
    - CMC_API_KEY: обязательна (ключ CoinMarketCap; для стаба подойдёт любое значение)
  ```

- **Необязательной переменной нет** — берётся значение по умолчанию из таблиц выше.
- **Файла `.env` нет совсем** — `docker compose up` работает на значениях по умолчанию (api на стабе); локальный api не стартует из-за `CMC_API_KEY`.
- **Нет ключей `BOOTSTRAP_*`** — api работает, ключи выпускаются командой `keys:create`; web не стартует и называет переменную.
